# 1. HTML5 Fundamentals — Questions 1–20

## 1. What is HTML5?

**HTML5** is the modern version of HTML used to structure and present content on the web.

It provides:

- Semantic elements
    
- Multimedia support
    
- Form enhancements
    
- Canvas
    
- SVG integration
    
- Web storage APIs
    
- Improved accessibility support
    
- APIs for modern web applications
    

Example:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>HTML5 Example</title>
</head>
<body>

  <header>
    <h1>My Website</h1>
  </header>

  <main>
    <section>
      <h2>Products</h2>
      <p>Product information.</p>
    </section>
  </main>

  <footer>
    Copyright 2026
  </footer>

</body>
</html>
```

### Interview Answer

> HTML5 is the modern HTML standard that provides semantic markup, multimedia elements, improved forms, graphics support and APIs required for modern web applications.

# 5. What is `<!DOCTYPE html>` and why is it required?

`<!DOCTYPE html>` tells the browser to interpret the document using **standards mode** for modern HTML.

```html
<!DOCTYPE html>
```

It is not an HTML element.

It is a **document type declaration**.

### Why?

Without the appropriate doctype, browsers may enter **quirks mode**, which can cause legacy rendering behavior.

### Interview Answer

> `<!DOCTYPE html>` tells the browser to use standards-based HTML rendering rather than legacy quirks behavior.

# 7. Semantic vs non-semantic elements?

### Semantic

The element describes its purpose.

```html
<nav>
  <a href="/home">Home</a>
</nav>
```

### Non-semantic

It doesn't communicate a specific content role.

```html
<div>
  <a href="/home">Home</a>
</div>
```

### Benefits of semantic HTML

- Accessibility
    
- SEO
    
- Maintainability
    
- Better document structure
    
- Easier interpretation by assistive technologies

# 18. What are block-level and inline elements?

### Block-level behavior

Traditionally, block elements begin on a new line and can take available horizontal space.

Examples:

```html
<div>
<p>
<section>
<article>
<header>
<footer>
```

### Inline behavior

Inline elements normally flow within surrounding text.

Examples:

```html
<span>
<a>
<strong>
<em>
```

### Important modern nuance

HTML semantics and CSS display behavior are different concepts. CSS can change an element's display behavior:

```css
span {
  display: block;
}
```

So don't treat "block element" as an immutable HTML property.

# 19. Difference between `id` and `class`?

### `id`

Identifies a particular element.

```html
<div id="header"></div>
```

Ideally unique within the document.

CSS:

```css
#header {
  background: black;
}
```

### `class`

Represents a reusable category.

```html
<div class="card"></div>
<div class="card"></div>
<div class="card"></div>
```

CSS:

```css
.card {
  padding: 20px;
}
```

### Interview Answer

> `id` identifies a specific element, while `class` is reusable across multiple elements and is generally preferred for styling.

# 20. Can multiple elements have the same `id`?

Technically browsers may still render the page, but **you should not do it**.

IDs are intended to be unique within a document.

Bad:

```html
<div id="user">John</div>
<div id="user">David</div>
```

Good:

```html
<div id="user-john">John</div>
<div id="user-david">David</div>
```

For repeated elements use:

```html
<div class="user">John</div>
<div class="user">David</div>
```

Duplicate IDs can cause problems with:

- CSS selectors
    
- JavaScript DOM APIs
    
- Accessibility relationships
    
- `<label for="">`
    
- Fragment navigation

# 32. How does the `required` attribute work?

```html
<input
  type="text"
  required>
```

The browser considers the field invalid if no value has been supplied.

When submitting the form, native constraint validation can prevent submission.

Example:

```html
<form>
  <input
    type="email"
    required>

  <button type="submit">
    Submit
  </button>
</form>
```

### Important

`required` is client-side validation.

Never rely on it for security.

---

# 33. What are `min` and `max`?

For numeric/date-like inputs they define allowable boundaries.

```html
<input
  type="number"
  min="1"
  max="10">
```

Valid:

```text
5
```

Invalid:

```text
15
```

For dates:

```html
<input
  type="date"
  min="2026-01-01"
  max="2026-12-31">
```

---

# 34. What are `minlength` and `maxlength`?

Used primarily for text-like values.

```html
<input
  type="text"
  minlength="8"
  maxlength="20">
```

The value must satisfy the specified length constraints for native constraint validation.

Example:

```text
"Angular"
```

Length = 7.

If:

```html
minlength="8"
```

the value is invalid.

---

# 35. Purpose of `pattern`?

`pattern` validates a value against a regular expression.

Example:

```html
<input
  type="text"
  pattern="[A-Za-z]{3,20}"
  required>
```

This allows letters with a length between 3 and 20.

Another example:

```html
<input
  type="text"
  pattern="[0-9]{6}"
  placeholder="6-digit PIN">
```

### Important

The pattern provides client-side constraint validation. Always validate untrusted input on the server too.

# 42. Difference between `autoplay`, `loop`, and `muted`?

### `autoplay`

Attempts to start playback automatically.

```html
<video autoplay>
```

### `loop`

Restarts media automatically after it reaches the end.

```html
<video loop>
```

### `muted`

Starts/keeps audio muted.

```html
<video muted>
```

They can be combined:

```html
<video
  autoplay
  muted
  loop
  playsinline>
</video>
```

---

# 43. Why is `muted` commonly required with autoplay?

Browsers commonly restrict **autoplay with audible audio** to prevent unwanted sound.

Therefore this pattern is common:

```html
<video
  autoplay
  muted
  playsinline>
</video>
```

Whether autoplay succeeds can depend on browser policies and user interaction.

### Interview Answer

> Browsers apply autoplay policies to protect users from unexpected audio. Muted autoplay is generally much more likely to be permitted.

```html
    kind="captions"
    src="captions-en.vtt"
    srclang="en"
```

```html
<video controls>

          type="video/mp4">

  <track
    kind="subtitles"
    src="english.vtt"
    srclang="en"
    label="English">

```

Example VTT:


### Accessibility

Captions are especially important for users who are deaf or hard of hearing. Subtitles and captions aren't always identical: captions generally include relevant non-speech audio information as well.

# 4. Canvas and SVG — Questions 46–55

## 46. What is HTML5 Canvas?

Canvas is a bitmap drawing surface that JavaScript can use to render graphics.

Typical use cases:

- Games
    
- Charts
    
- Image manipulation
    
- Simulations
    
- Drawing applications
    
- Real-time visualization
    

Example:

```html
<canvas
  id="myCanvas"
  width="500"
  height="300">
</canvas>
```

JavaScript accesses its rendering context.

---

# 47. What is the `<canvas>` element?

`canvas` creates a drawable area.

```html
<canvas
  id="canvas"
  width="500"
  height="300">
</canvas>
```

Then:

```js
const canvas =
  document.getElementById('canvas');

const ctx =
  canvas.getContext('2d');
```

`ctx` is the 2D drawing context.

---

# 48. Difference between Canvas and SVG?

This is a very common interview question.

|Canvas|SVG|
|---|---|
|Raster/bitmap drawing surface|Vector graphics|
|Pixel-oriented rendering|Object/element-oriented|
|Graphics aren't individual DOM elements|SVG elements are part of DOM|
|Good for many dynamic pixels|Good for scalable shapes|
|Excellent for games|Excellent for diagrams/icons|
|JavaScript often drives rendering|Can be manipulated via DOM/CSS/JS|
|Scaling can reduce visual quality|Scales without losing vector quality|

Example SVG:

```html
<svg width="200" height="100">
  <circle
    cx="50"
    cy="50"
    r="40">
  </circle>
</svg>
```

### Simple rule

```text
Canvas → pixels / high-frequency drawing

SVG → shapes / DOM / scalable graphics
```

---

# 49. When should you use Canvas instead of SVG?

Canvas is a strong choice for:

- Games
    
- Particle systems
    
- Real-time visualizations
    
- Image processing
    
- Large numbers of rapidly changing pixels
    
- Drawing applications
    

Example:

```text
Game
 ↓
Thousands of moving objects
 ↓
Canvas
```

SVG is often preferable for:

```text
Business diagram
Organization chart
Interactive map shapes
Icons
Accessible data visualization
```

---

# 50. What is a 2D rendering context?

The 2D rendering context provides JavaScript APIs for drawing on Canvas.

```js
const canvas =
  document.getElementById('canvas');

const ctx =
  canvas.getContext('2d');
```

Then:

```js
ctx.fillRect(10, 10, 100, 50);
```

You can perform operations such as:

- Draw rectangles
    
- Draw paths
    
- Draw text
    
- Draw images
    
- Apply transformations
    
- Set colors/styles
    

---

# 51. How do you draw a rectangle using Canvas?

```html
<canvas
  id="canvas"
  width="400"
  height="200">
</canvas>
```

```js
const canvas =
  document.getElementById('canvas');

const ctx =
  canvas.getContext('2d');

ctx.fillRect(
  50,
  50,
  150,
  80
);
```

The arguments are:

```text
x
y
width
height
```

For an outline:

```js
ctx.strokeRect(
  50,
  50,
  150,
  80
);
```

---

# 52. How do you draw a line using Canvas?

Use a path:

```js
const canvas =
  document.getElementById('canvas');

const ctx =
  canvas.getContext('2d');

ctx.beginPath();

ctx.moveTo(50, 50);

ctx.lineTo(250, 100);

ctx.stroke();
```

Conceptually:

```text
beginPath()
     ↓
moveTo()
     ↓
lineTo()
     ↓
stroke()
```

---

# 53. How do you draw text using Canvas?

Use `fillText()`:

```js
ctx.font = '24px Arial';

ctx.fillText(
  'Hello Angular',
  50,
  80
);
```

For an outline:

```js
ctx.strokeText(
  'Hello Angular',
  50,
  120
);
```

# 54. Can Canvas be used for animations?

Yes.

A common approach is `requestAnimationFrame()`.

```js
function animate() {

  ctx.clearRect(
    0,
    0,
    canvas.width,
    canvas.height
  );

  // Draw updated frame

  requestAnimationFrame(animate);
}

animate();
```

Conceptually:

```text
Frame 1
 ↓
Clear
 ↓
Update state
 ↓
Draw
 ↓
requestAnimationFrame
 ↓
Frame 2
 ↓
```

# 5. HTML5 Storage — Questions 56–65

## 56. What is Web Storage?

### Concept

Web Storage is a browser API that allows a web application to store **key-value data on the client side**.

It provides two main objects:

```javascript
localStorage
sessionStorage
```

Both store values as **strings**.

### Example

```javascript
localStorage.setItem("username", "Ashok");

const username = localStorage.getItem("username");
```

### Interview Answer

> Web Storage provides client-side key-value storage through localStorage and sessionStorage. It is simpler than cookies and is commonly used for non-sensitive application state and preferences.

# 57. What is `localStorage`?

### Concept

`localStorage` stores data associated with the current origin and normally persists until it is explicitly removed or otherwise cleared.

```javascript
localStorage.setItem("theme", "dark");
```

Even after refreshing the page:

```javascript
localStorage.getItem("theme");
```

returns:

```text
dark
```

### Example

```javascript
localStorage.setItem("language", "en");

console.log(
    localStorage.getItem("language")
);
```

### Interview Answer

> localStorage is persistent, origin-scoped browser storage used for client-side key-value data. It survives page reloads and normally browser restarts until the data is removed.

---

# 58. What is `sessionStorage`?

### Concept

`sessionStorage` stores data for the current page session.

```javascript
sessionStorage.setItem("step", "2");
```

It is useful for temporary state such as:

- Multi-step form progress
    
- Temporary filters
    
- Wizard state
    
- Current-page session information
    

### Example

```javascript
sessionStorage.setItem(
    "checkoutStep",
    "2"
);

const step =
    sessionStorage.getItem("checkoutStep");
```

### Interview Answer

> sessionStorage provides temporary browser storage associated with a page session. It is useful when data should not persist as long as localStorage.

# 63. What is the `storage` event?

The `storage` event lets another document of the same origin observe changes to Web Storage.

# 64. What are the limitations of Web Storage?

Important limitations:

### 1. String-based

Everything is stored as strings.

```javascript
localStorage.setItem(
    "count",
    100
);
```

When retrieved:

```javascript
typeof localStorage.getItem("count");
```

is:

```text
"string"
```

---

### 2. Limited capacity

Browser quotas are implementation-dependent.

Don't assume a universal fixed limit such as exactly 5 MB.

---

### 3. Synchronous API

Operations are synchronous, so excessive use can affect responsiveness.

---

### 4. No complex querying

Unlike IndexedDB, Web Storage doesn't provide a database/query model.

---

### 5. Same-origin restrictions

Storage is associated with the document's origin.

---

### 6. XSS exposure

JavaScript running in the page can access Web Storage.

---

### 7. Not suitable for large data

For larger structured client-side data, consider:

```text
IndexedDB
```

# 65. Why should sensitive information generally not be stored in localStorage?

This is a **very common security interview question**.

Suppose you store an authentication token:

```javascript
localStorage.setItem(
    "accessToken",
    token
);
```

If an attacker manages to execute malicious JavaScript through an XSS vulnerability, that JavaScript can potentially read:

```javascript
localStorage.getItem(
    "accessToken"
);
```

### Better Architecture

For browser authentication, an appropriately designed server-side session or token architecture using cookies with controls such as:

```text
HttpOnly
Secure
SameSite
```

can reduce exposure to JavaScript.

### Senior Interview Answer

> I generally avoid putting sensitive authentication credentials in localStorage because JavaScript can read them. If an XSS vulnerability exists, an attacker may steal those credentials. For browser authentication, I would consider secure HttpOnly cookies with appropriate SameSite and CSRF protections as part of the overall security architecture.

# 86. How does a Service Worker enable offline applications?

A simplified architecture:

```text
             Browser
                │
                ▼
        Service Worker
          /          \
      Cache          Network
        │               │
        ▼               ▼
   Cached data       Server
```

During installation, resources can be cached:

```javascript
self.addEventListener(
    "install",
    event => {

        event.waitUntil(
            caches.open("app-v1")
                .then(cache =>
                    cache.addAll([
                        "/",
                        "/index.html",
                        "/styles.css",
                        "/app.js"
                    ])
                )
        );
    }
);
```

Then the fetch event can choose an appropriate response:

```javascript
self.addEventListener(
    "fetch",
    event => {

        event.respondWith(
            caches.match(
                event.request
            ).then(cachedResponse => {

                return cachedResponse ||
                       fetch(event.request);
            })
        );
    }
);
```

### Important

This is only one caching strategy. Real applications may use:

```text
Cache First
Network First
Stale While Revalidate
Network Only
Cache Only
```

depending on the resource.

# 10. Web Workers

Web Workers execute JavaScript in a background thread separate from the main UI thread.

### Main thread

```javascript
const worker = new Worker("worker.js");

worker.postMessage(100);

worker.onmessage = event => {
    console.log(event.data);
};
```

### worker.js

```javascript
self.onmessage = event => {
    const result = event.data * 2;

    self.postMessage(result);
};
```

### Why?

Suppose you perform CPU-intensive processing:

```text
Large calculation
Image processing
Data transformation
Complex computation
```

Doing it on the browser main thread can make the UI unresponsive.

A Worker can move suitable CPU-heavy work away from the main thread.

### Interview Answer

> "A Web Worker allows JavaScript to perform CPU-intensive work in a separate thread so the main UI thread remains responsive."

### Important limitation

A normal dedicated Worker doesn't directly manipulate the DOM.

# 13. Cache API

The Cache API allows Service Workers and other supported contexts to store request/response pairs.

### Open cache

```javascript
    "/styles.css",

```

### Retrieve

```javascript
const response = await caches.match("/index.html");
```

### Delete old cache

```javascript
await caches.delete("v1");
```

### Common caching strategies

```text
Cache First
Network First
Stale While Revalidate
Cache Only
Network Only
```

```javascript
self.addEventListener("fetch", event => {
```
