# 1. CSS Fundamentals — Questions 1–20

## 1. What is CSS?

### Concept

CSS stands for **Cascading Style Sheets**. It controls the presentation and layout of HTML elements.

CSS handles:

- Colors
    
- Fonts
    
- Spacing
    
- Layout
    
- Responsive design
    
- Animations
    
- Positioning
    
- Visual states
    

### Example

```html
<h1 class="title">Hello CSS</h1>
```

```css
.title {
    color: blue;
    font-size: 32px;
}
```

### Interview Answer

> CSS is a stylesheet language used to control the presentation, layout, appearance, and responsive behavior of HTML documents.

---

# 2. What are the different ways to apply CSS?

There are three traditional approaches:

### 1. Inline CSS

```html
<p style="color: red;">
    Hello
</p>
```

### 2. Internal CSS

```html
<style>
    p {
        color: red;
    }
</style>
```

### 3. External CSS

```html
<link rel="stylesheet" href="styles.css">
```

```css
p {
    color: red;
}
```

### Recommended

For maintainable applications:

> **External CSS or component-scoped styles are preferred over large amounts of inline styling.**

# 3. Inline vs Internal vs External CSS

|Type|Location|Reusable|Recommended|
|---|---|--:|---|
|Inline|HTML element|❌|Rarely|
|Internal|`<style>`|Within document|Sometimes|
|External|`.css` file|✅|Usually|

### Example

```html
<p style="color:red">Inline</p>
```

```html
<style>
p { color: red; }
</style>
```

```html
<link rel="stylesheet" href="styles.css">
```

# 4. Advantages of External CSS

Example:

```html
<link rel="stylesheet" href="styles.css">
```

Advantages:

- Reusable across pages
    
- Easier maintenance
    
- Better separation of concerns
    
- Browser caching can reduce repeated downloads
    
- Cleaner HTML
    
- Easier team collaboration
    
- Better scalability
    

### Architect Answer

> For large applications, I prefer external or component-scoped styles with a consistent design system because it improves maintainability, reuse, caching, and separation of concerns.

# 5. What is a CSS selector?

A selector determines **which HTML elements a CSS rule targets**.

```css
p {
    color: red;
}
```

Here:

```text
p → selector
color: red → declaration
```

Another example:

```css
.card {
    padding: 20px;
}
```

---

# 6. Types of CSS selectors

Important selectors:

### Element

```css

```

### Class

```css

```

### ID

```css

```

### Universal

```css
* {}
```

### Attribute

```css

```

### Descendant

```css
.container p {}
```

### Child

```css
.container > p {}
```

### Adjacent sibling


### General sibling


### Pseudo-class


### Pseudo-element

```css

```

# 7. What is an element selector?

Targets elements by their HTML tag name.

```css
p {
    color: blue;
}
```

This applies to all matching `<p>` elements.

```html
<p>Hello</p>
<p>World</p>
```

---

# 8. What is a class selector?

Targets elements having a particular class.

```css
.card {
    border: 1px solid black;
}
```

HTML:

```html
<div class="card">Product 1</div>
<div class="card">Product 2</div>
```

Both elements receive the style.

### Interview Answer

> Class selectors are reusable and are generally preferred for styling groups of elements.

---

# 9. What is an ID selector?

Targets an element with a specific ID.

```css
#header {
    background: black;
}
```

HTML:

```html
<header id="header">
</header>
```

### Important

IDs are intended to be unique in a document.

For reusable styling, classes are generally preferable.

---

# 10. What is an attribute selector?

Targets elements based on attributes.

```css
input[type="email"] {
    border: 1px solid blue;
}
```

Other examples:

```css
a[target="_blank"] {}

input[required] {}

input[name^="user"] {}
```

Useful for styling based on semantic attributes or states.

---

# 11. What is the universal selector?

The universal selector is:

```css
*
```

Example:

```css
* {
    box-sizing: border-box;
}
```

It targets all elements.

A common reset/base rule is:

```css
*,
*::before,
*::after {
    box-sizing: border-box;
}
```

---

# 12. What are descendant and child selectors?

### Descendant

Uses a space:

```css
.container p {
    color: red;
}
```

Targets any `<p>` inside `.container`, at any nesting depth.

```html
<div class="container">
    <section>
        <p>Hello</p>
    </section>
</div>
```

---

### Child

Uses `>`:

```css
.container > p {
    color: blue;
}
```

Only targets a direct child.

---

# 13. Difference between `>` and space

This is a common interview question.

### Descendant

```css
.parent .child
```

Means:

> `.child` can be anywhere inside `.parent`.

### Child

```css
.parent > .child
```

Means:

> `.child` must be a direct child of `.parent`.

Example:

```html
<div class="parent">
    <div>
        <p class="child">Hello</p>
    </div>
</div>
```

```css
.parent .child {
    color: red;
}
```

Matches.

```css
.parent > .child {
    color: blue;
}
```

Doesn't match because `.child` isn't a direct child.

---

# 14. Adjacent sibling vs general sibling

## Adjacent sibling `+`

Targets the **immediately following sibling**.

```css
h2 + p {
    margin-top: 0;
}
```

```html
<h2>Title</h2>
<p>Matched</p>
```

---

## General sibling `~`

Targets subsequent matching siblings.

```css
h2 ~ p {
    color: gray;
}
```

Example:

```html
<h2>Title</h2>
<div>Something</div>
<p>Matched</p>
<p>Also matched</p>
```

### Easy Rule

```text
+ → immediately next sibling
~ → later siblings
```

---

# 15. What is CSS specificity?

Specificity determines which competing CSS declaration has greater priority when declarations apply to the same element and property.

Example:

```css
p {
    color: blue;
}

.text {
    color: red;
}
```

```html
<p class="text">
    Hello
</p>
```

The class selector has greater specificity than the element selector, so the text is red.

---

# 16. How is CSS specificity calculated?

A useful mental model is:

```text
Inline styles
      ↓
ID selectors
      ↓
Class / attribute / pseudo-class
      ↓
Element / pseudo-element
```

You can represent this as a tuple:

```text
(a, b, c, d)
```

Where:

- `a` = inline declarations
    
- `b` = ID selectors
    
- `c` = class/attribute/pseudo-class selectors
    
- `d` = element/pseudo-element selectors
    

Example:

```css
#app .card p {
    color: red;
}
```

Specificity:

```text
ID       = 1
Class    = 1
Element  = 1
```

Conceptually:

```text
(0,1,1,1)
```

Compare:

```css
.card p
```

which is:

```text
(0,0,1,1)
```

The first is more specific.

### Important Senior Point

Specificity is only part of the cascade. You also need to consider:

- Origin
    
- Importance
    
- Cascade layers
    
- Specificity
    
- Source order
    

---

# 17. What is the CSS cascade?

The **cascade** is the mechanism browsers use to determine which CSS declarations apply when multiple rules target the same property.

Conceptually:

```text
Multiple CSS declarations
          ↓
Cascade rules
          ↓
Winning declaration
```

For example:

```css
p {
    color: blue;
}

.text {
    color: red;
}
```

```html
<p class="text">Hello</p>
```

The `.text` rule wins because it has greater specificity.

### Senior Point

Don't reduce the cascade to simply "last rule wins."

The browser considers the applicable cascade rules, including origin/importance, layers, specificity, and source order.

---

# 18. What is inheritance in CSS?

Inheritance means some CSS properties automatically receive their value from the parent element.

Example:

```css
body {
    color: blue;
}
```

```html
<body>
    <div>
        <p>Hello</p>
    </div>
</body>
```

The text color can inherit from `body`.

### Common inherited properties

```text
color
font-family
font-size
line-height
```

Not every CSS property inherits.

---

# 19. Inherited vs non-inherited properties

### Common inherited properties

```css
color
font-family
font-size
line-height
```

### Common non-inherited properties

```css
margin
padding
border
width
height
background
```

Example:

```css
body {
    color: blue;
    margin: 20px;
}
```

A child generally inherits the color but doesn't automatically inherit the body's margin.

### Useful CSS keywords

```css
color: inherit;
```

Explicitly inherit.

```css
margin: initial;
```

Use the property's initial value.

```css
color: unset;
```

Reset according to whether the property naturally inherits.

---

# 20. What does `!important` do?

`!important` increases the priority of a declaration within the cascade's importance rules.

```css
.title {
    color: red !important;
}
```

It can override many competing normal declarations.

### Why avoid excessive use?

```css
.title {
    color: red !important;
}

.header .title {
    color: blue !important;
}
```

Now maintenance becomes difficult.

### Better approach

Fix:

- Selector specificity
    
- Cascade layers
    
- Component architecture
    
- Source ordering
    

rather than repeatedly adding `!important`.

### Interview Answer

> `!important` marks a declaration as important in the cascade. It can be useful for controlled exceptions, but excessive use creates specificity and maintenance problems.

# 2. CSS Box Model — Questions 21–30

# 21. What is the CSS Box Model?

Every element is conceptually represented as a box consisting of:

```text
       Margin
    ┌───────────────┐
    │    Border     │
    │ ┌───────────┐ │
    │ │  Padding  │ │
    │ │ ┌───────┐ │ │
    │ │ │Content│ │ │
    │ │ └───────┘ │ │
    │ └───────────┘ │
    └───────────────┘
```

---

# 22. Four components of the Box Model

```text
1. Content
2. Padding
3. Border
4. Margin
```

Example:

```css
.card {
    width: 300px;
    padding: 20px;
    border: 2px solid black;
    margin: 30px;
}
```

---

# 23. Margin vs padding

### Padding

Space **inside** the border.

```css
.card {
    padding: 20px;
}
```

### Margin

Space **outside** the border.

```css
.card {
    margin: 20px;
}
```

Visual:

```text
Margin
  ↓
┌───────────────┐
│    Border     │
│ ┌───────────┐ │
│ │  Padding  │ │
│ │ Content   │ │
│ └───────────┘ │
└───────────────┘
```

### Easy Rule

> **Padding = inside**  
> **Margin = outside**

---

# 24. Border vs outline

### Border

```css
button {
    border: 2px solid black;
}
```

Border participates in the box model.

### Outline

```css
button {
    outline: 2px solid blue;
}
```

Outline is drawn outside the border and does not take up normal layout space.

### Important Accessibility Point

Don't remove focus outlines without providing an accessible replacement.

Bad:

```css
button:focus {
    outline: none;
}
```

Better:

```css
button:focus-visible {
    outline: 2px solid currentColor;
    outline-offset: 2px;
}
```

---

# 25. What is `box-sizing`?

`box-sizing` determines how the declared width and height relate to the element's box dimensions.

Two important values:

```css
box-sizing: content-box;
```

and:

```css
box-sizing: border-box;
```

---

# 26. `content-box` vs `border-box`

## content-box

Default for many elements.

```css
.box {
    width: 300px;
    padding: 20px;
    border: 5px solid;
}
```

Actual outer width:

```text
300 + 20 + 20 + 5 + 5
= 350px
```

---

## border-box

```css
.box {
    box-sizing: border-box;
    width: 300px;
    padding: 20px;
    border: 5px solid;
}
```

The declared width includes content + padding + border.

Outer width:

```text
300px
```

---

# 27. Why is `box-sizing: border-box` commonly used?

Because dimensions become easier to reason about.

Common global rule:

```css
*,
*::before,
*::after {
    box-sizing: border-box;
}
```

Now:

```css
.card {
    width: 300px;
    padding: 20px;
    border: 2px solid;
}
```

The outer width remains:

```text
300px
```

### Interview Answer

> `border-box` makes the declared width and height include padding and border, which generally simplifies responsive layouts and component sizing.

---

# 28. How is actual width calculated?

With `content-box`:

```text
Outer width =
content width
+ left padding
+ right padding
+ left border
+ right border
+ left margin
+ right margin
```

Example:

```css
.box {
    width: 300px;
    padding: 20px;
    border: 5px solid;
    margin: 10px;
}
```

Element's border-box width:

```text
300 + 40 + 10
= 350px
```

If considering total layout space including margins:

```text
350 + 20
= 370px
```

With `border-box`, declared width already includes content + padding + border.

---

# 29. What is margin collapsing?

Vertical margins of certain block elements can **collapse** rather than add together.

Example:

```css
.first {
    margin-bottom: 30px;
}

.second {
    margin-top: 20px;
}
```

You might expect:

```text
30 + 20 = 50px
```

But in a normal block formatting context, the margins can collapse to approximately:

```text
30px
```

rather than 50px.

### Important

Margin collapsing is primarily a **vertical block-flow behavior** and has specific rules. It does not occur in the same way for flex/grid containers.

---

# 30. How can you prevent margin collapsing?

Several approaches can establish a boundary that prevents the relevant margins from collapsing.

### Use padding

```css
.parent {
    padding-top: 1px;
}
```

### Use border

```css
.parent {
    border-top: 1px solid transparent;
}
```

### Create a new formatting context

For example:

```css
.parent {
    display: flow-root;
}
```

### Use Flexbox/Grid

```css
.parent {
    display: flex;
    flex-direction: column;
}
```

### Senior Answer

> Margin collapsing occurs in certain normal block-flow situations. I usually avoid depending on it in component layouts and use explicit padding, `flow-root`, flexbox, or grid when I need predictable spacing.

# 3. Display & Positioning — Questions 31–45

# 31. What is the `display` property?

`display` controls how an element participates in layout.

Common values:

```text
block
inline
inline-block
flex
grid
none
contents
```

Example:

```css
.container {
    display: flex;
}
```

---

# 32. Difference between block, inline and inline-block

## Block

```css
div {
    display: block;
}
```

Generally:

- Starts on a new line
    
- Can have width/height
    
- Occupies available inline space by default
    

---

## Inline

```css
span {
    display: inline;
}
```

Generally:

- Flows within text
    
- Width/height don't behave like block dimensions
    
- Vertical margins/padding have special inline-flow behavior
    

---

## Inline-block

```css
span {
    display: inline-block;
}
```

Combines characteristics:

- Flows inline with surrounding content
    
- Can have width and height
    

### Comparison

|Property|Block|Inline|Inline-block|
|---|---|---|---|
|New line|Yes|No|No|
|Width/height|Yes|Limited|Yes|
|Flows inline|No|Yes|Yes|

---

# 33. What is `display: none`?

```css
.menu {
    display: none;
}
```

The element is removed from the layout.

Conceptually:

```text
Element
   ↓
No box generated
   ↓
No layout space
```

It is also generally not exposed as normal visible content to assistive technologies.

---

# 34. `display: none` vs `visibility: hidden`

### `display: none`

```css
display: none;
```

Element doesn't participate in layout.

### `visibility: hidden`

```css
visibility: hidden;
```

Element remains in the layout but is not visible.

```text
display:none

A   B   C
    ↑
 hidden element takes no space


visibility:hidden

A   [space]   C
       ↑
 hidden element still occupies space
```

---

# 35. `visibility: hidden` vs `opacity: 0`

### `visibility: hidden`

```css
visibility: hidden;
```

Element is invisible and generally not interactive.

### `opacity: 0`

```css
opacity: 0;
```

Element becomes fully transparent, but it still participates in layout and can still receive interaction/focus depending on the element and other CSS.

This makes `opacity: 0` potentially surprising.

### Interview Answer

> `visibility:hidden` hides the element while preserving its layout space. `opacity:0` makes it transparent but doesn't inherently remove it from layout or interaction.

---

# 36. What is the `position` property?

`position` controls how an element is positioned relative to its normal layout or a containing block.

Main values:

```text
static
relative
absolute
fixed
sticky
```

---

# 37. Explain static, relative, absolute, fixed and sticky

## `static`

Default positioning.

```css
.box {
    position: static;
}
```

`top`, `left`, `right`, and `bottom` don't reposition a statically positioned element.

---

## `relative`

```css
.box {
    position: relative;
    top: 10px;
}
```

The element remains in normal flow while being visually offset.

It also commonly establishes a containing block for absolutely positioned descendants.

---

## `absolute`

```css
.box {
    position: absolute;
    top: 20px;
    right: 20px;
}
```

The element is removed from normal flow and positioned relative to its containing block.

---

## `fixed`

```css
.box {
    position: fixed;
    right: 20px;
    bottom: 20px;
}
```

Normally positioned relative to the viewport and remains fixed during scrolling, subject to containing-block rules created by certain ancestors.

---

## `sticky`

```css
.header {
    position: sticky;
    top: 0;
}
```

Behaves approximately like a relatively positioned element until a specified scroll threshold is reached, then sticks within its scroll container's relevant bounds.

---

# 38. Relative vs absolute positioning

### Relative

```css
.box {
    position: relative;
    top: 10px;
}
```

The element remains part of normal flow.

Its original space remains reserved.

### Absolute

```css
.box {
    position: absolute;
    top: 10px;
}
```

The element is removed from normal flow.

### Example

```html
<div class="parent">
    <div class="child">
        Hello
    </div>
</div>
```

```css
.parent {
    position: relative;
}

.child {
    position: absolute;
    top: 10px;
    right: 10px;
}
```

The child is positioned relative to the appropriate containing block established by `.parent`.

---

# 39. What is the containing block of an absolutely positioned element?

This is a **frequent senior CSS question**.

An absolutely positioned element is positioned relative to its **containing block**.

A common pattern:

```css
.parent {
    position: relative;
}

.child {
    position: absolute;
    top: 0;
    right: 0;
}
```

Here `.parent` commonly establishes the containing block.

Without such an ancestor, the containing block may come from an appropriate ancestor or the initial containing block, depending on the positioning/layout context.

### Easy Interview Rule

> `position: relative` on a parent + `position: absolute` on a child is a common way to create a local positioning context.

---

# 40. How does `position: fixed` work?

Example:

```css
.chat-button {
    position: fixed;
    right: 20px;
    bottom: 20px;
}
```

It normally remains attached to the viewport while the document scrolls.

Typical uses:

- Floating buttons
    
- Fixed headers
    
- Chat widgets
    
- Cookie controls
    

### Important Senior Point

Certain properties on ancestors, notably transforms and some related properties, can affect the containing block of a fixed-position descendant. Therefore, `fixed` does not always behave as though the viewport is its containing block in every layout situation.

---

# 41. How does `position: sticky` work?

Example:

```css
.header {
    position: sticky;
    top: 0;
}
```

It participates in normal flow and becomes stuck when the scroll position reaches its threshold.

Conceptually:

```text
Normal scrolling
       ↓
Element reaches top: 0
       ↓
Element sticks
       ↓
Containing scroll area ends
       ↓
Element stops sticking
```

---

# 42. Why might `position: sticky` not work?

Very common interview question.

### 1. Missing offset

Bad:

```css
.header {
    position: sticky;
}
```

Better:

```css
.header {
    position: sticky;
    top: 0;
}
```

---

### 2. Incorrect scroll container

An ancestor with scrolling/overflow behavior can change which container controls sticky positioning.

---

### 3. Not enough scrolling space

If the containing area is too small, there may be no opportunity for sticky behavior.

---

### 4. Layout interactions

Certain combinations involving:

- Flexbox
    
- Grid
    
- Overflow
    
- Container sizing
    

can make sticky behavior appear broken.

### Debugging Approach

Inspect:

```text
position
top/bottom
overflow
height
scroll container
parent layout
```

---

# 43. What is `z-index`?

`z-index` controls stacking order for positioned elements and certain other layout/stacking contexts.

Example:

```css
.modal {
    position: fixed;
    z-index: 1000;
}

.header {
    position: fixed;
    z-index: 100;
}
```

The modal is intended to appear above the header.

### Important

A larger `z-index` doesn't necessarily beat every element on the page because stacking contexts isolate z-index comparisons.

---

# 44. What is a stacking context?

A **stacking context** is a conceptual three-dimensional stacking environment in which elements are painted relative to each other.

Certain conditions can create stacking contexts, including:

- Root element
    
- Positioned elements with non-auto `z-index` in relevant cases
    
- `position: fixed` / `sticky` in relevant cases
    
- `opacity < 1`
    
- `transform` other than `none`
    
- `isolation: isolate`
    
- Certain `contain`, `will-change`, and other CSS features
    

Example:

```css
.parent {
    transform: translateZ(0);
}
```

This can create a new stacking context.

Inside that context:

```css
.child {
    z-index: 999999;
}
```

still cannot simply escape the parent's stacking context and appear above an unrelated sibling stacking context.

---

# 45. Why does `z-index` sometimes appear not to work?

This is one of the **most important CSS debugging questions**.

Suppose:

```css
.parent-a {
    position: relative;
    z-index: 1;
}

.child {
    position: absolute;
    z-index: 99999;
}
```

And another sibling:

```css
.parent-b {
    position: relative;
    z-index: 2;
}
```

Even though:

```text
child z-index = 99999
```

the entire `.parent-a` stacking context may still be below `.parent-b`.

Conceptually:

```text
Parent A
 z-index: 1
   └── Child
       z-index: 99999

Parent B
 z-index: 2
```

The child cannot use `99999` to escape Parent A's stacking context.

### Other reasons `z-index` appears broken

Check:

1. Is the element participating in the expected stacking context?
    
2. Does an ancestor create a stacking context?
    
3. Is another stacking context above it?
    
4. Is `position`/layout context relevant?
    
5. Is `transform`, `opacity`, `filter`, or `isolation` creating a context?
    
6. Is the element being clipped by `overflow`?
    
7. Is the problem actually clipping rather than stacking?
    

### Senior Interview Answer

> `z-index` is not a global layer number. It is evaluated within stacking contexts. If an ancestor creates a lower stacking context, increasing the child's z-index cannot make it escape that context. I debug the stacking-context hierarchy rather than blindly increasing z-index values.

# 4. Flexbox — Questions 46–60

## 46. What is CSS Flexbox?

### Concept

**Flexbox (Flexible Box Layout)** is a one-dimensional CSS layout system used to arrange elements in a **row or column** and control their alignment, spacing, sizing, and distribution.

It is especially useful for:

- Navigation bars
    
- Toolbars
    
- Cards
    
- Centering content
    
- Form layouts
    
- Responsive components
    

### Example

```css
.container {
  display: flex;
}
```

```html
<div class="container">
  <div>Item 1</div>
  <div>Item 2</div>
  <div>Item 3</div>
</div>
```

### Interview Answer

> Flexbox is a one-dimensional CSS layout system designed to distribute and align elements along a main axis and cross axis.

---

# 47. What problem does Flexbox solve?

### Concept

Before Flexbox, developers commonly used:

- Floats
    
- Tables
    
- Inline-block
    
- Positioning hacks
    

Flexbox simplifies:

- Horizontal/vertical alignment
    
- Equal distribution
    
- Dynamic sizing
    
- Responsive layouts
    
- Spacing between elements
    

### Example

Center an element:

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

### Interview Answer

> Flexbox solves common alignment and distribution problems, especially when the size of elements or available space changes dynamically.

---

# 48. How do you create a Flexbox container?

Use:

```css
.container {
  display: flex;
}
```

or:

```css

  display: inline-flex;
}
```

`display: flex` creates a block-level flex container.

`display: inline-flex` creates an inline-level flex container.

# 49. What is the difference between the main axis and cross axis?

The axes depend on `flex-direction`.

```text
    ↓
    ↓
```

For:

```css

```

```text
Main axis
   ↓
   ↓
   ↓

Cross axis → → →
```

### Interview Answer

> The main axis follows `flex-direction`, while the cross axis is perpendicular to it.

# 5. CSS Grid — Questions 61–72

## 61. What is CSS Grid?

CSS Grid is a **two-dimensional layout system** designed to control both:

- Rows
    
- Columns
    

It is excellent for:

- Page layouts
    
- Dashboards
    
- Card grids
    
- Complex responsive layouts
    

Example:

```css
.container {
  display: grid;
}
```

---

# 62. Grid vs Flexbox

|Feature|Flexbox|Grid|
|---|---|---|
|Dimension|One-dimensional|Two-dimensional|
|Primary focus|Row/column|Rows + columns|
|Content-driven layouts|Excellent|Good|
|Page layouts|Good|Excellent|
|Complex grids|Limited|Excellent|

### Interview Answer

> Flexbox is primarily one-dimensional, while Grid is two-dimensional. I typically use Flexbox for component-level alignment and Grid for larger page or matrix-like layouts.

# 63. How do you create a Grid container?

```css
.container {
  display: grid;
}
```

Or:

```css
.container {
  display: inline-grid;
}
```

---

# 64. What are grid rows and columns?

Grid divides a container into:

```text
Column 1 | Column 2 | Column 3
---------+----------+---------
Row 1    |          |
---------+----------+---------
Row 2    |          |
```

Example:

```css
.container {
  display: grid;
  grid-template-columns: 200px 1fr 200px;
  grid-template-rows: 100px 1fr;
}
```

---

# 65. What does grid-template-columns do?

It defines the size and structure of grid columns.

```css
grid-template-columns: 200px 1fr 200px;
```

Creates:

```text
200px | flexible | 200px
```

Another example:

```css
grid-template-columns: repeat(3, 1fr);
```

Creates three equal columns.

---

# 66. What does grid-template-rows do?

Defines grid row sizes.

```css
grid-template-rows: 100px 1fr 50px;
```

Example page:

```text
Header → 100px
Content → flexible
Footer → 50px
```

---

# 67. What is the `fr` unit?

`fr` means **fraction of the available space** in a grid container.

```css
grid-template-columns: 1fr 2fr;
```

Available space is divided:

```text
1 part | 2 parts
```

So approximately:

```text
33.33% | 66.67%
```

after accounting for gaps and other constraints.

---

# 68. What does gap do in CSS Grid?

```css
.container {
  display: grid;
  gap: 20px;
}
```

It creates spacing between grid tracks.

You can also use:

```css
row-gap: 10px;
column-gap: 20px;
```

---

# 69. What are grid-column and grid-row?

They control where an item is placed in the grid.

```css
.item {
  grid-column: 1 / 3;
}
```

The item spans from grid line 1 to line 3.

Similarly:

```css
.item {
  grid-row: 1 / 3;
}
```

---

# 70. What is grid-template-areas?

It allows you to visually describe a layout.

```css
.container {
  display: grid;

  grid-template-areas:
    "header header"
    "sidebar content"
    "footer footer";
}
```

Then:

```css
.header {
  grid-area: header;
}

.sidebar {
  grid-area: sidebar;
}

.content {
  grid-area: content;
}

.footer {
  grid-area: footer;
}
```

This is highly readable for application layouts.

---

# 71. What are auto-fit and auto-fill?

They are commonly used with responsive grids.

### `auto-fit`

Attempts to fit as many columns as possible and can collapse empty tracks.

```css
grid-template-columns:
  repeat(auto-fit, minmax(200px, 1fr));
```

### `auto-fill`

Creates as many tracks as can fit, potentially preserving empty tracks.

```css
grid-template-columns:
  repeat(auto-fill, minmax(200px, 1fr));
```

### Practical pattern

For responsive cards:

```css
.cards {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(250px, 1fr));
  gap: 20px;
}
```

This can often reduce the need for many media queries.

---

# 72. How can CSS Grid create a responsive layout?

Example:

```css
.cards {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(250px, 1fr));
  gap: 1rem;
}
```

The browser automatically determines how many columns fit.

### Interview Answer

> CSS Grid supports responsive layouts using flexible units such as `fr`, `minmax()`, `auto-fit`, and `auto-fill`, often reducing the number of breakpoint-specific rules.

# 80. What is `clamp()` in CSS?

# 94. What are `@keyframes`?

`@keyframes` defines stages of a CSS animation.

```css
@keyframes slide {
  from {
    transform: translateX(0);
  }

    transform: translateX(100px);
  }
}
```

Apply:

```css
.box {
```


# 95. How can you optimize CSS animations for performance?

Prefer animating properties such as:

```css
transform
opacity
```

Example:

```css
transform: translateX(100px);
opacity: 0.5;
```

Avoid frequently animating layout-affecting properties such as:

```css
width
height
top
left
margin
```

when a transform can achieve the same visual result.

### Also consider

```css
will-change: transform;
```

But don't apply `will-change` indiscriminately.

Respect user preferences:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms;
    animation-iteration-count: 1;
    transition-duration: 0.01ms;
  }
}
```

### Interview Answer

> For smooth animations, I prefer compositor-friendly properties such as `transform` and `opacity`, minimize layout-triggering changes, avoid unnecessary `will-change`, and respect `prefers-reduced-motion`.

Unused styles increase download and processing costs.

### 2. Minify CSS

Production builds should minify CSS.

### 3. Reduce duplication

Avoid repeating the same rules unnecessarily.

### 4. Keep selectors manageable

Avoid deeply nested selectors:

```css

}
```

Prefer:

```css

```

### 5. Use code splitting where appropriate

Large applications can load styles based on feature/module requirements.

### 6. Prefer modern layout systems

Use:

```text

Grid
```

instead of old layout hacks.

### 7. Optimize fonts

Fonts can significantly affect rendering performance.

### 8. Avoid unnecessary animations

Especially expensive layout-triggering animations.

### Interview Answer

> I optimize CSS by removing unused rules, minimizing and splitting CSS where appropriate, reducing specificity and duplication, optimizing fonts, and avoiding unnecessary layout-triggering styles and animations.

# 99. What causes CSS rendering and layout performance problems?

A browser generally goes through stages such as:

```text
Style calculation
      ↓
Layout
      ↓
Paint
      ↓
Composite
```

### Layout problems

Changing properties such as:

```css
width
height
margin
padding
top
left
```

can require layout recalculation.

### Paint-heavy properties

Examples can include:

```text
large shadows
complex filters
large visual effects
```

### Composite-friendly changes

Often preferable:

```css
transform
opacity
```

### Common causes

- Excessive DOM complexity
    
- Large stylesheets
    
- Expensive selectors
    
- Frequent layout changes
    
- Forced synchronous layout
    
- Excessive animations
    
- Huge paint areas
    

### Senior-level interview answer

> Performance problems occur when style recalculation, layout, painting, or compositing becomes expensive or happens too frequently. I profile the issue rather than assuming a particular CSS property is always expensive.

# 1. CSS Cascade

The cascade determines **which CSS declaration wins** when multiple declarations target the same element/property.

A simplified mental model is:

```text
Origin / importance
       ↓
Cascade layers
       ↓
Specificity
       ↓
Source order
```

Example:

```css
p {
    color: blue;
}

p {
    color: red;
}
```

Result:

```text
red
```

because the declarations have equivalent precedence and the later declaration wins.

### Senior Interview Answer

> "The cascade is the mechanism CSS uses to resolve competing declarations. I don't think of it simply as 'last rule wins'; importance, origin, cascade layers, specificity and source order all participate."

---

# 2. Specificity Calculation

A useful interview model:

```text
Inline styles
    ↓
ID selectors
    ↓
Class / attribute / pseudo-class
    ↓
Element / pseudo-element
```

Example:

```css
#app .card p {
    color: red;
}

.card p {
    color: blue;
}
```

The first selector wins because it contains an ID.

### Specificity notation

Think of:

```text
(A, B, C, D)
```

where conceptually:

```text
A = inline declarations
B = IDs
C = classes, attributes, pseudo-classes
D = elements and pseudo-elements
```

Example:

```css
#app .card p
```

Conceptually:

```text
(0, 1, 1, 1)
```

### Important senior traps

Don't treat:

```css
!important
```

as simply "highest specificity."

`!important` participates in the cascade's importance rules, and multiple important declarations can still be resolved using later cascade criteria.

Also understand that:

```css
:is(...)
:has(...)
:not(...)
```

have specificity behavior that depends on their arguments.

```css
}
```

But many properties don't naturally inherit:

```text

width

```

### Control inheritance

```css
.child {
    color: inherit;
}
```

Other useful global keywords:

```css
initial
inherit
unset
revert
revert-layer
```

### Senior Answer

> "Inheritance allows certain CSS properties to obtain their computed value from an ancestor when no overriding declaration applies. It is property-specific, not a universal behavior."

# 4. Box Model

Every normal CSS box is conceptually composed of:

```text
┌───────────────────────────┐
│          Margin           │
│  ┌─────────────────────┐  │
│  │       Border        │  │
│  │ ┌─────────────────┐ │  │
│  │ │     Padding     │ │  │
│  │ │ ┌─────────────┐ │ │  │
│  │ │ │   Content   │ │ │ │
│  │ │ └─────────────┘ │ │  │
│  │ └─────────────────┘ │  │
│  └─────────────────────┘  │
└───────────────────────────┘
```

With default `content-box`:

```css
width: 200px;
padding: 20px;
border: 5px solid;
```

Actual outer width:

```text
200 + 20 + 20 + 5 + 5
= 250px
```

# 5. `box-sizing`

```css
box-sizing: content-box;
```

Declared width applies to the **content area**.

### `border-box`

```css

```

Declared width includes:

```text
content + padding + border
```

Common enterprise pattern:

```css
*,
*::before,
*::after {
    box-sizing: border-box;
}
```

### Senior Answer

> "I generally use border-box because component dimensions become easier to reason about: declared width and height include padding and borders."

# 6. Margin Collapsing

Vertical margins of certain block boxes can **collapse** instead of adding together.

```css
.first {
    margin-bottom: 30px;
}

.second {
    margin-top: 20px;
}
```

The resulting gap can be:

```text
30px
```

rather than:

```text
50px
```

This behavior occurs in specific normal-flow block formatting contexts.

It generally doesn't behave the same way inside:

```text
Flex containers
Grid containers
```

### Interview Answer

> "Margin collapsing is a normal-flow behavior where adjoining vertical margins can combine into a single margin. I don't rely on it for component spacing in large systems; I prefer explicit layout mechanisms such as gap, padding, or container layout."

# 7. Positioning

Know these extremely well:

```css
position: static;
position: relative;
position: absolute;
position: fixed;
position: sticky;
```

### Relative

```css
.card {
    position: relative;
}
```

Remains in normal flow and can establish a containing block for absolutely positioned descendants.

### Absolute

```css
.badge {
    position: absolute;
    top: 0;
    right: 0;
}
```

Removed from normal flow.

### Fixed

```css
.chat {
    position: fixed;
    right: 20px;
    bottom: 20px;
}
```

Normally positioned relative to the viewport, although certain ancestor properties can affect its containing block behavior.

### Sticky

```css
.header {
    position: sticky;
    top: 0;
}
```

Acts relative to normal flow until a threshold is reached, then sticks within its scroll/container constraints.

# 8. Stacking Context

This is where many senior candidates make mistakes.

A stacking context is an independent 3D ordering context for painting.

Certain conditions can create stacking contexts, including examples such as:

```css
position: relative;
z-index: 10;
```

and properties such as:

```css
transform
opacity < 1
filter
isolation: isolate
```

among others.

### Critical rule

A child cannot simply use a huge `z-index` to escape its ancestor's stacking context.

For example:

```text
Parent stacking context
    │
    ├── Child z-index: 999999
    │
    └── Other stacking context
```

The child is still constrained by its parent's stacking context.

### Senior Answer

> "When z-index appears broken, I first inspect stacking contexts rather than increasing z-index values."

---

# 9. `z-index`

`z-index` controls stacking order where the relevant boxes participate in a stacking context.

```css
.modal {
    position: fixed;
    z-index: 1000;
}
```

But:

```text
z-index: 999999
```

doesn't guarantee that an element appears above everything.

Why?

```text
Stacking context
    ↓
Child stacking order
    ↓
Other stacking context
```

### Senior debugging sequence

When `z-index` doesn't work:

1. Is the element participating in the expected positioning/layout?
    
2. Which stacking context is it in?
    
3. Did an ancestor create another stacking context?
    
4. Is another stacking context painted above it?
    
5. Is clipping caused by `overflow` or another containment boundary?


# 11. Flex Sizing Algorithm

This is a **genuine senior-level topic**.

Suppose:

```css
.item {
    flex: 1 1 200px;
}
```

This means:

```text
flex-grow:   1
flex-shrink: 1
flex-basis:  200px
```

Conceptually:

```text
flex-basis
     ↓
Determine hypothetical sizes
     ↓
Compare total size with container
     ↓
Free space?
   ↙       ↘
Grow      Shrink
```

### Example

```css
.container {
    display: flex;
    width: 600px;
}

.item {
    flex: 1;
}
```

Three items will generally share available free space equally, subject to min/max constraints and the details of the flex sizing algorithm.

### Important trap

Flex items have automatic minimum sizing behavior that can surprise developers, especially with long text or nested content.

A common fix in certain layouts is:

```css
.item {
    min-width: 0;
}
```

### Senior Answer

> "Flex sizing starts from the flex base size and then distributes positive or negative free space according to grow or shrink factors, while respecting minimum and maximum constraints. I also check automatic minimum sizing when a flex item unexpectedly refuses to shrink."

# 12. Flexbox vs Grid

|Flexbox|Grid|
|---|---|
|One-dimensional|Two-dimensional|
|Row OR column|Rows AND columns|
|Content-oriented|Layout-oriented|
|Excellent for components|Excellent for page layouts|
|Navigation/toolbars|Dashboard layouts|

### Senior answer

> "I use Flexbox when the layout is primarily along one axis and Grid when I need coordinated row-and-column layout. They complement each other rather than compete."

# 13. CSS Grid

```css
.container {
    display: grid;

    grid-template-columns:
        repeat(3, 1fr);

    gap: 20px;
}
```

`fr` represents a flexible fraction of the available grid space.

Example:

```css
grid-template-columns: 1fr 2fr;
```

The available space is distributed in a 1:2 proportion after accounting for relevant fixed sizing and gaps.

### Named areas

```css
.layout {
    display: grid;

    grid-template-areas:
        "header header"
        "sidebar main"
        "footer footer";
}
```

# 14. `auto-fit` vs `auto-fill`

Very common responsive Grid question.

```css
grid-template-columns:
    repeat(auto-fit, minmax(200px, 1fr));
```

### `auto-fit`

Fits as many tracks as possible and can collapse empty tracks, allowing existing items to expand.

### `auto-fill`

Creates as many tracks as fit, retaining empty tracks when space permits.

### Practical rule

For responsive cards:

```css
grid-template-columns:
    repeat(auto-fit, minmax(250px, 1fr));
```

is often what you want.

# 17. `rem` vs `em`

### `rem`

Relative to the root element's font size.

```css
html {
    font-size: 16px;
}

.title {
    font-size: 2rem;
}
```

Approximately:

```text

```

### `em`

Relative to the relevant element's computed font size for many properties, which can compound through nesting.

```css
.parent {
    font-size: 20px;
}

.child {
    font-size: 1.5em;
}
```

Approximately:

```text
30px
```

### Senior Recommendation

Use `rem` for many global spacing/type scales and use `em` when intentionally coupling sizing to the component's current font size.


# 19. Container Queries

Media queries generally respond to the **viewport**.

Container queries allow a component to respond to the **size of its containing context**.

```css
.card-container {
    container-type: inline-size;
}
```

Then:

```css
@container (min-width: 500px) {
    .card {
        display: grid;
        grid-template-columns: 1fr 2fr;
    }
}
```

### Why important?

It makes components more reusable.

A card doesn't need to know whether it is inside:

```text
Desktop page
Sidebar
Modal
Dashboard
Mobile layout
```

It can respond to its own available container size.

### Senior Answer

> "Media queries are viewport/environment-oriented, while container queries allow components to adapt to their containing layout context. Container queries are particularly valuable for reusable design-system components."

# 23. CSS Animation Performance



# 25. Enterprise CSS Performance

For an enterprise application, don't only ask:

> "Is the CSS file small?"

Look at the complete rendering pipeline:

```text

 ↓

 ↓

 ↓

 ↓

```

### Common optimization areas

**1. Reduce unnecessary CSS**

Remove unused styles where practical.

**2. Avoid excessive selector complexity**

Prefer predictable, shallow selectors.

**3. Reduce layout thrashing**

Avoid patterns that repeatedly mix DOM writes and synchronous layout reads.

**4. Prefer compositor-friendly animation**

Often:


**5. Code splitting**

Load styles according to application needs where architecture permits.

**6. Design tokens**
