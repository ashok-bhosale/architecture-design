# JavaScript Interview Questions 1–50

Below is a **senior-level interview preparation guide** in the same format: **Concept → Example → Interview Answer**. I’ll also highlight common interview traps.

---

# 1. What is JavaScript?

### Concept

JavaScript is a **high-level, dynamically typed, multi-paradigm programming language** primarily used to make web applications interactive.

It supports:

- Procedural programming
    
- Object-oriented programming
    
- Functional programming
    
- Asynchronous programming
    

JavaScript runs in browsers and also on servers using environments such as Node.js.

### Interview Answer

> JavaScript is a dynamically typed, multi-paradigm programming language used for client-side and server-side application development. It supports object-oriented, functional, and asynchronous programming models.

---

# 2. What are the different data types in JavaScript?

JavaScript has **7 primitive types** plus objects.

### Primitive

```text
string
number
bigint
boolean
undefined
symbol
null
```

### Non-primitive

```text
object
```

Arrays, functions, dates, maps, sets, etc. are objects in JavaScript's type system.

Example:

```js
let name = "Ashok";       // string
let age = 39;             // number
let active = true;        // boolean
let value;                // undefined
let empty = null;         // null
let id = Symbol("id");    // symbol
let big = 123n;           // bigint
let user = { name };      // object
```

### Interview Answer

> JavaScript has seven primitive types—string, number, bigint, boolean, undefined, symbol, and null—and objects as the non-primitive category.

---

# 3. Difference between `null` and `undefined`

|`undefined`|`null`|
|---|---|
|Value not assigned/available|Intentional absence of value|
|Usually produced by JavaScript|Usually explicitly assigned|
|`typeof` → `"undefined"`|`typeof` → `"object"`|
|Default value of uninitialized variables|Used to represent "no value"|

Example:

```js
let a;
console.log(a); // undefined

let b = null;
console.log(b); // null
```

### Important Interview Trap

```js
typeof null
```

returns:

```text
"object"
```

This is a historical JavaScript behavior.

---

# 4. What is `NaN`?

`NaN` means **Not-a-Number**.

It represents an invalid numeric result.

```js
const result = "hello" / 2;

console.log(result); // NaN
```

Interestingly:

```js
typeof NaN
```

returns:

```text
"number"
```

### Checking NaN

Prefer:

```js
Number.isNaN(value)
```

Example:

```js
Number.isNaN(NaN); // true
```

### Interview Answer

> `NaN` is a special numeric value representing an invalid or unrepresentable numeric result. Its type is `number`.

---

# 5. Difference between `==` and `===`

### `==`

Performs **type coercion** before comparison in many cases.

```js
5 == "5"; // true
```

### `===`

Strict equality checks value and type.

```js
5 === "5"; // false
```

Another important example:

```js
0 == false;  // true
0 === false; // false
```

### Best Practice

Prefer:

```js
===
```

unless you intentionally need loose equality semantics.

---

# 6. What are truthy and falsy values?

A value is **truthy** if JavaScript treats it as true in a Boolean context.

Common falsy values include:

```text
false
0
-0
0n
""
null
undefined
NaN
```

Almost everything else is truthy, including:

```js
[]
{}
"0"
"false"
```

Example:

```js
if ("hello") {
  console.log("Truthy");
}
```

### Interview Trap

```js
if ([]) {
   // executes
}
```

An empty array is **truthy**.

# 7. What is type coercion?

Type coercion is JavaScript converting one type into another.

### Implicit coercion

```js
"5" + 2
```

Result:

```text
"52"
```

Because `+` with a string performs string concatenation.

But:

```js
"5" - 2
```

results in:

```text
3
```

because subtraction converts the string to a number.

### Explicit conversion

```js
Number("5");
String(10);
Boolean(1);
```

### Interview Answer

> Type coercion is the conversion of a value from one type to another, either implicitly by JavaScript or explicitly by the developer.

---

# 8. What is hoisting?

Hoisting describes how JavaScript's execution setup makes declarations available according to their declaration type before execution reaches their source position.

Example:

```js
console.log(x);

var x = 10;
```

Result:

```text
undefined
```

Conceptually:

```js
var x;
console.log(x);
x = 10;
```

But `let` and `const` behave differently because they are in the **Temporal Dead Zone** before initialization.

---

# 9. How does variable hoisting work?

### `var`

```js
console.log(a); // undefined

var a = 10;
```

The declaration is hoisted; initialization remains where it occurs.

### `let`

```js
console.log(b); // ReferenceError

let b = 20;
```

### `const`

```js
console.log(c); // ReferenceError

const c = 30;
```

### Interview Answer

> `var` declarations are hoisted and initialized to `undefined`, while `let` and `const` are hoisted in the execution model but remain inaccessible in the Temporal Dead Zone until initialization.

That is more accurate than simply saying "`let` and `const` aren't hoisted."

---

# 10. What is scope in JavaScript?

Scope determines **where a variable can be accessed**.

Major scopes include:

```text
Global scope
Function scope
Block scope
Module scope
```

Example:

```js
const globalValue = 10;

function test() {
  const localValue = 20;

  console.log(globalValue); // 10
  console.log(localValue);  // 20
}
```

---

# 11. Global scope vs local scope

### Global

```js
const name = "Ashok";

function test() {
  console.log(name);
}
```

`name` is accessible inside the function.

### Local

```js
function test() {
  const age = 39;
}

console.log(age); // ReferenceError
```

`age` exists only inside the function scope.

### Interview Answer

> Global variables are accessible throughout their applicable global/module environment, while local variables are restricted to their function, block, or module scope depending on how they are declared.

---

# 12. What is block scope?

A block is code surrounded by `{}`.

`let` and `const` are block-scoped.

```js
if (true) {
  let x = 10;
  const y = 20;
}

console.log(x); // ReferenceError
console.log(y); // ReferenceError
```

`var` is **not block-scoped**:

```js
if (true) {
  var z = 30;
}

console.log(z); // 30
```

---

# 13. What is a closure?

A closure occurs when a function retains access to variables from its **lexical environment**, even after the outer function has finished executing.

Example:

```js
function counter() {
  let count = 0;

  return function () {
    return ++count;
  };
}

const increment = counter();

console.log(increment()); // 1
console.log(increment()); // 2
console.log(increment()); // 3
```

The returned function retains access to `count`.

---

# 14. Practical example of closures

Closures are commonly used for **private state**.

```js
function createBankAccount(initialBalance) {
  let balance = initialBalance;

  return {
    deposit(amount) {
      balance += amount;
    },

    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount(1000);

account.deposit(500);

console.log(account.getBalance()); // 1500
```

The `balance` variable isn't directly exposed.

### Interview Answer

> Closures are useful for encapsulation, factories, callbacks, event handlers, memoization, and maintaining state between function calls.

---

# 15. What is lexical scope?

Lexical scope means variable accessibility is determined by **where code is written**, not where a function is called.

Example:

```js
const x = 10;

function outer() {
  const y = 20;

  function inner() {
    console.log(x);
    console.log(y);
  }

  inner();
}
```

`inner()` can access variables based on where it was defined.

---

# 16. What is the `this` keyword?

`this` refers to a context determined by **how a function is called**, with important differences for arrow functions.

Example:

```js
const user = {
  name: "Ashok",

  greet() {
    console.log(this.name);
  }
};

user.greet();
```

Output:

```text
Ashok
```

---

# 17. How does `this` behave in different contexts?

This is a very common interview question.

### Object method

```js
const user = {
  name: "Ashok",

  greet() {
    console.log(this.name);
  }
};

user.greet();
```

`this` refers to `user`.

### Regular function

In strict mode:

```js
"use strict";

function test() {
  console.log(this);
}
```

`this` is `undefined` when called as a plain function.

### Constructor

```js
function User(name) {
  this.name = name;
}

const user = new User("Ashok");
```

`this` refers to the newly created instance.

### Arrow function

Arrow functions don't have their own `this`.

```js
const user = {
  name: "Ashok",

  greet: () => {
    console.log(this.name);
  }
};
```

Don't use an arrow function as an object method when you need the object's `this`.

### `call`, `apply`, `bind`

```js
function greet() {
  console.log(this.name);
}

greet.call({ name: "Ashok" });
```

# 18. What are primitive data types?

Primitive values are immutable values representing a single value.

JavaScript primitives:

```text
string
number
bigint
boolean
undefined
symbol
null
```

Example:

```js
let x = 10;
let y = x;

y = 20;

console.log(x); // 10
```

Changing `y` doesn't change `x`.

# 19. What are reference data types?

In common JavaScript terminology, objects are often called reference types.

Examples:

```js
const user = {
  name: "Ashok"
};

const numbers = [1, 2, 3];

const date = new Date();
```

Functions are also objects.

Important nuance:

> JavaScript variables are always passed by value. For objects, the value being passed is a reference to the object.

This distinction is important in interviews.

---

# 20. Pass-by-value vs pass-by-reference

A common oversimplification is saying:

> "Primitive = pass by value, object = pass by reference."

More precisely, **JavaScript is pass-by-value**.

For an object, the value copied is a reference to that object.

Example:

```js
const user = {
  name: "Ashok"
};

function update(obj) {
  obj.name = "John";
}

update(user);

console.log(user.name);
```

Output:

```text
John
```

Because both variables' values refer to the same object.

But:

```js
function replace(obj) {
  obj = { name: "John" };
}

replace(user);

console.log(user.name);
```

The original object isn't replaced.

### ⭐ Senior Interview Answer

> JavaScript uses pass-by-value. When an object is passed, the copied value is a reference to the same object, which is why object mutation is visible to the caller, but reassigning the parameter isn't.

# 21. What is an IIFE?

IIFE = **Immediately Invoked Function Expression**.

It is a function expression that executes immediately.

```js
(function () {
  console.log("Executed immediately");
})();
```

Arrow version:

```js
(() => {
  console.log("Hello");
})();
```

Historically, IIFEs were commonly used to create private scope before ES modules and block-scoped declarations became standard.

# 22. What are callbacks?

A callback is a function passed to another function to be invoked later or as part of an operation.

```js
function processUser(name, callback) {
  callback(name);
}

processUser("Ashok", function (name) {
  console.log(name);
});
```

Common examples:

```js
setTimeout(...)
array.map(...)
array.filter(...)
array.forEach(...)
```

# 23. What are higher-order functions?

A higher-order function either:

1. Accepts a function as an argument, or
    
2. Returns a function.
    

Example:

```js
function calculate(a, b, operation) {
  return operation(a, b);
}

const result = calculate(10, 5, (x, y) => x + y);

console.log(result); // 15
```

`calculate` is a higher-order function.

---

# 24. What are pure functions?

A pure function:

1. Produces the same output for the same input.
    
2. Has no observable side effects.
    

Example:

```js
function add(a, b) {
  return a + b;
}
```

Same inputs:

```js
add(2, 3); // 5
add(2, 3); // 5
```

Impure example:

```js
let total = 0;

function add(amount) {
  total += amount;
}
```

It changes external state.

---

# 25. What are side effects in functions?

A side effect is an observable change outside the function's local computation.

Examples:

```text
Modifying global state
Changing an external object
Writing to a database
Making an HTTP request
Logging
DOM manipulation
Reading/writing external systems
```

Example:

```js
let count = 0;

function increment() {
  count++;
}
```

The function changes external state, so it has a side effect.

# 26. Function Declaration vs Function Expression

### Function Declaration

```js
function add(a, b) {
  return a + b;
}
```

### Function Expression

```js
const add = function (a, b) {
  return a + b;
};
```

One important difference is hoisting behavior.

Function declarations can generally be called before their declaration:

```js
sayHello();

function sayHello() {
  console.log("Hello");
}
```

A function expression assigned to `const` cannot be called before initialization.

# 27. What are arrow functions?

Arrow functions provide a concise function syntax.

```js
const add = (a, b) => {
  return a + b;
};
```

Short form:

```js
const add = (a, b) => a + b;
```

Single parameter:

```js
const square = x => x * x;
```

---

# 28. Arrow functions vs regular functions

|Arrow Function|Regular Function|
|---|---|
|Lexically captures `this`|`this` determined by invocation|
|No own `arguments`|Has `arguments`|
|Cannot be used with `new`|Can be constructor|
|Concise syntax|Traditional syntax|
|No own `prototype`|Function objects can have `prototype`|

### Important

Arrow functions are particularly useful for callbacks:

```js
const numbers = [1, 2, 3];

const doubled = numbers.map(x => x * 2);
```

# 29. What are default parameters?

Default parameters provide a value when an argument is `undefined`.

```js
function greet(name = "Guest") {
  return `Hello ${name}`;
}

greet(); // Hello Guest
```

But:

```js
greet(undefined);
```

also uses the default.

Whereas:

```js
greet(null);
```

passes `null`; the default isn't used.

---

# 30. What are rest parameters?

Rest parameters collect remaining arguments into an array.

```js
function sum(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}

sum(1, 2, 3, 4);
```

`numbers` becomes:

```js
[1, 2, 3, 4]
```

### Important

Rest parameter must be the final parameter:

```js
function test(a, ...rest) {}
```

---

# 31. What is the spread operator?

Spread syntax expands an iterable or object into another context.

### Array

```js
const a = [1, 2];
const b = [...a, 3, 4];

console.log(b);
```

Result:

```text
[1, 2, 3, 4]
```

### Object

```js
const user = {
  name: "Ashok"
};

const updatedUser = {
  ...user,
  age: 39
};
```

### Rest vs Spread

Same syntax:

```text
...
```

But:

```text
Rest   → collects
Spread → expands
```

# 32. What are template literals?

Template literals use backticks:

```js
const name = "Ashok";

const message = `Hello ${name}`;
```

They support:

- String interpolation
    
- Multiline strings
    
- Embedded expressions
    

Example:

```js
const a = 10;

```

# 33. What is object destructuring?

It extracts properties into variables.

```js
const user = {
  name: "Ashok",
  age: 39
};

const { name, age } = user;
```

Rename:

```js
const { name: userName } = user;
```

Default:

```js
const { city = "Mumbai" } = user;
```

---

# 34. What is array destructuring?

It extracts values based on position.

```js
const numbers = [10, 20, 30];

const [a, b, c] = numbers;
```

Skip:

```js
const [first, , third] = numbers;
```

Rest:

```js
const [first, ...remaining] = numbers;
```

# 35. What are computed property names?

They allow an expression to determine an object's property name.

```js
const key = "name";

const user = {
  [key]: "Ashok"
};
```

Result:

```js
{
  name: "Ashok"
}
```

Another example:

```js
const prefix = "user";

const obj = {
  [`${prefix}Name`]: "Ashok"
};
```

# 36. What is object shorthand syntax?

If property and variable names are the same:

```js
const name = "Ashok";
const age = 39;

const user = {
  name,
  age
};
```

Instead of:

```js
const user = {
  name: name,
  age: age
};
```

Methods can also use shorthand:

```js
const user = {
  greet() {
    console.log("Hello");
  }
};
```

# 37. What is `Object.freeze()`?

`Object.freeze()` prevents an object's properties from being:

- Added
    
- Deleted
    
- Changed
    

Example:

```js
const user = {
  name: "Ashok"
};

Object.freeze(user);

user.name = "John";

console.log(user.name);
```

The assignment doesn't change the frozen object's property in normal non-strict code.

### Important

`Object.freeze()` is **shallow**.

```js
const user = {
  address: {
    city: "Mumbai"
  }
};

Object.freeze(user);

user.address.city = "Pune";
```

The nested object can still be changed unless it is also frozen.

---

# 38. What is `Object.seal()`?

`Object.seal()` prevents:

- Adding properties
    
- Deleting properties
    

But existing properties can generally still be modified if they are writable.

```js
const user = {
  name: "Ashok"
};

Object.seal(user);

user.name = "John"; // allowed
user.age = 39;      // not allowed
delete user.name;   // not allowed
```

### Freeze vs Seal

|Freeze|Seal|
|---|---|
|Add ❌|Add ❌|
|Delete ❌|Delete ❌|
|Modify existing properties ❌|Modify existing writable properties ✅|

Both are shallow.

---

# 39. `Object.assign()` vs spread operator

Both are commonly used for **shallow copying/merging** objects.

### `Object.assign()`

```js
const target = {};

Object.assign(target, user);
```

It mutates the target object.

### Spread

```js
const copy = {
  ...user
};
```

Creates a new object.

### Important

Both are shallow:

```js
const copy = { ...user };
```

Nested objects remain shared references.

# 40. What are prototypes in JavaScript?

Every ordinary object has a prototype from which it can inherit properties and methods.

Example:

```js
const user = {
  name: "Ashok"
};

console.log(user.toString());
```

`toString()` is inherited through the object's prototype chain.

You can inspect an object's prototype with:

```js
Object.getPrototypeOf(user);
```

---

# 41. What is prototype inheritance?

Prototype inheritance means an object can access properties and methods from another object through its prototype chain.

Example:

```js
const animal = {
  speak() {
    console.log("Animal sound");
  }
};

const dog = Object.create(animal);

dog.speak();
```

`dog` doesn't own `speak`; it finds it through its prototype.

---

# 42. How does the prototype chain work?

When JavaScript evaluates:

```js
dog.speak()
```

it approximately searches:

```text
dog
 ↓
dog's prototype
 ↓
prototype's prototype
 ↓
...
 ↓
null
```

If the property isn't found anywhere:

```js
undefined
```

is normally returned for property access.

# 43. `__proto__` vs `prototype`

This is a **very common interview question**.

### `prototype`

A property found on constructor functions/classes that is used as the prototype for instances created through `new`.

```js
function User() {}

console.log(User.prototype);
```

### `__proto__`

An accessor historically used to get/set an object's prototype.

```js
const user = {};

console.log(user.__proto__);
```

Prefer:

```js
Object.getPrototypeOf(user);
```

and:

```js
Object.setPrototypeOf(user, prototype);
```

### Key difference

```text
Constructor function
       |
       └── prototype
              ↓
          instance
              |
              └── [[Prototype]]
```

The instance's internal `[[Prototype]]` points to the constructor's `prototype`.

---

# 44. What are constructor functions?

Before ES6 classes, constructor functions were a common way to create objects with shared methods.

```js
function User(name) {
  this.name = name;
}

User.prototype.greet = function () {
  console.log(`Hello ${this.name}`);
};

const user = new User("Ashok");

user.greet();
```

When called with `new`, JavaScript creates an object whose prototype is `User.prototype` and invokes the constructor with that object as `this`.

---

# 45. What are ES6 classes?

Classes provide a cleaner syntax for JavaScript's prototype-based object model.

```js
class User {
  constructor(name) {
    this.name = name;
  }

  greet() {
    console.log(`Hello ${this.name}`);
  }
}

const user = new User("Ashok");

user.greet();
```

Important:

> JavaScript classes do not replace prototypes; class methods are still implemented using the prototype mechanism.

---

# 46. What is inheritance in JavaScript?

Inheritance allows one class/object to reuse behavior from another.

Using classes:

```js
class Animal {
  speak() {
    console.log("Animal sound");
  }
}

class Dog extends Animal {
  bark() {
    console.log("Woof");
  }
}

const dog = new Dog();

dog.speak();
dog.bark();
```

`Dog` inherits `speak()` from `Animal`.

---

# 47. What is method overriding?

A child class provides its own implementation of a method inherited from its parent.

```js
class Animal {
  speak() {
    console.log("Animal sound");
  }
}

class Dog extends Animal {
  speak() {
    console.log("Woof");
  }
}
```

Now:

```js
const dog = new Dog();

dog.speak();
```

Output:

```text
Woof
```

Parent implementation can be accessed with:

```js
super.speak();
```

---

# 48. What is polymorphism?

Polymorphism means the same interface/method call can produce different behavior depending on the object.

```js
class Animal {
  speak() {
    console.log("Animal sound");
  }
}

class Dog extends Animal {
  speak() {
    console.log("Woof");
  }
}

class Cat extends Animal {
  speak() {
    console.log("Meow");
  }
}

const animals = [new Dog(), new Cat()];

animals.forEach(animal => animal.speak());
```

Output:

```text
Woof
Meow
```

### Interview Answer

> Polymorphism allows different objects to respond to the same operation according to their own implementation.

---

# 49. What is encapsulation in JavaScript?

Encapsulation means keeping implementation details/state controlled behind a public interface.

Modern JavaScript supports private class fields:

```js
class BankAccount {
  #balance = 0;

  deposit(amount) {
    this.#balance += amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount();

account.deposit(1000);

console.log(account.getBalance());
```

This won't work:

```js
account.#balance;
```

because `#balance` is private.

Closures are another way to encapsulate state.

# 50. What are static methods?

Static methods belong to the **class itself**, not to individual instances.

```js
class MathUtil {
  static add(a, b) {
    return a + b;
  }
}

console.log(MathUtil.add(10, 20));
```

You don't call it through an instance:

```js
const obj = new MathUtil();

obj.add(10, 20); // TypeError
```

### Typical use

Static methods are useful for:

- Utility operations
    
- Factory methods
    
- Operations that don't require instance state
    

Example:

```js
class User {
  constructor(name) {
    this.name = name;
  }

  static createGuest() {
    return new User("Guest");
  }
}

const guest = User.createGuest();
```

# 4. ES6 Features — Questions 51–65

## 51. What are `let`, `const`, and `var`?

All three declare variables, but their behavior differs.

|Feature|`var`|`let`|`const`|
|---|---|---|---|
|Scope|Function|Block|Block|
|Redeclaration in same scope|✅|❌|❌|
|Reassignment|✅|✅|❌|
|TDZ|❌|✅|✅|
|Hoisted|Yes|Yes*|Yes*|

Example:

```js
var a = 10;

let b = 20;

const c = 30;
```

`const` prevents reassignment of the variable binding, but does **not make an object immutable**:

```js
const user = {
  name: "Ashok"
};

user.name = "John"; // Allowed
```

### Interview Answer

> I prefer `const` by default, use `let` when reassignment is required, and generally avoid `var` in modern JavaScript because of its function scope and historical hoisting behavior.

# 52. What is the Temporal Dead Zone (TDZ)?

The TDZ is the period between entering a scope and the point where a `let`, `const`, or `class` declaration is initialized.

```js
console.log(name); // ReferenceError

let name = "Ashok";
```

The variable exists in the scope but cannot be accessed before initialization.

### Compare

```js
console.log(x); // undefined
var x = 10;
```

versus:

```js
console.log(y); // ReferenceError
let y = 10;
```

### Interview Answer

> TDZ is the period during which a `let`, `const`, or class binding exists but cannot be accessed before its initialization.


Benefits:

- Encapsulation
    
- Reusability
    
- Dependency management
    
- Static module structure
    
- Better tooling
    
- Tree-shaking opportunities

# 54. Difference between `import` and `require`

`import` belongs to the **ES module system**.

```js
import { add } from "./math.js";
```

`require()` is traditionally associated with **CommonJS**.

```js
const { add } = require("./math");
```

|ES Modules|CommonJS|
|---|---|
|`import/export`|`require/module.exports`|
|Standard JavaScript module system|Traditional Node.js module system|
|Static module syntax|Runtime function-style loading|
|Supports modern tree-shaking workflows|Different tooling model|

### Node.js Note

Modern Node.js supports both module systems, depending on project configuration and file/module context.

### Interview Answer

> `import/export` is the standard ECMAScript module system, while `require/module.exports` is CommonJS. In modern applications, I generally prefer ES modules unless the project specifically requires CommonJS.

# 57. What are iterators?

# 59. What does the `yield` keyword do?

`yield`:

1. Produces a value.
    
2. Pauses generator execution.
    
3. Allows execution to resume later.
    

```js

  console.log("B");
```

> `yield` pauses a generator and returns a value to the caller. Calling `next()` resumes execution from that point.

# 61. What are Maps?

`Map` is a collection of key-value pairs.

# 62. What are WeakMaps?

`WeakMap` stores key-value pairs where keys must be objects or non-registered symbols, and its keys are held weakly.

```js
const metadata = new WeakMap();

const user = {};

metadata.set(user, {
  role: "admin"
});
```

A key property is that WeakMap is designed to avoid keeping an otherwise unreachable object alive solely because it is used as a key.

### Important

WeakMap is not enumerable:

```js
// No map.keys()
// No map.values()
// No map.forEach()
```

### Common use

Attaching private metadata to objects without creating an ordinary strong reference from a collection.

A `Set` stores **unique values**.

Useful methods:

# 64. What are WeakSets?

`WeakSet` stores objects (and non-registered symbols in current ECMAScript) weakly.

```js
const processed = new WeakSet();

const user = {};

processed.add(user);

console.log(processed.has(user));
```

Like WeakMap, it is not enumerable.

### Common use

Tracking whether particular objects have been processed without creating a strong collection reference that would by itself keep those objects alive.

# 65. When should Maps be preferred over Objects?

Use `Map` when you need a true key-value collection.

### Prefer Map when:

- Keys aren't naturally strings/symbols.
    
- You need frequent additions/removals.
    
- You need `size`.
    
- You need straightforward iteration.
    
- You want collection-specific APIs.
    

```js
const cache = new Map();

cache.set(userObject, response);
```

### Prefer Object when:

You're representing a structured record:

```js
const user = {
  name: "Ashok",
  age: 39
};
```

### Interview Answer

> I use objects for structured records and Maps for dynamic key-value collections, especially when keys can be arbitrary values or when collection operations and iteration are important.

# 5. Arrays and Methods — Questions 66–75

## 66. Difference between `map()` and `forEach()`

### `map()`

Transforms an array and returns a **new array**.

```js
const numbers = [1, 2, 3];

const doubled = numbers.map(x => x * 2);

console.log(doubled);
// [2, 4, 6]
```

### `forEach()`

Executes a function for each element but doesn't create a transformed result array.

```js
numbers.forEach(x => {
  console.log(x);
});
```

|`map()`|`forEach()`|
|---|---|
|Returns new array|Returns `undefined`|
|Transformation|Side-effect/iteration|
|Chainable|Not chainable via return value|

### Interview Answer

> Use `map()` when transforming data and `forEach()` when performing an action for each item.

# 67. What is `filter()`?

`filter()` returns a new array containing elements that satisfy a condition.

```js
const numbers = [1, 2, 3, 4, 5];

const even = numbers.filter(x => x % 2 === 0);

// [2, 4]
```

It doesn't mutate the original array.

# 68. What is `reduce()`?

`reduce()` reduces an array to a single accumulated result.

```js
const numbers = [1, 2, 3, 4];

const total = numbers.reduce(
  (sum, number) => sum + number,
  0
);

console.log(total);
// 10
```

The result doesn't have to be a number.

It can produce:

```text
object
array
string
Map
any other value
```

Example grouping:

```js
const users = [
  { name: "A", role: "admin" },
  { name: "B", role: "user" },
  { name: "C", role: "admin" }
];

const grouped = users.reduce((result, user) => {
  (result[user.role] ??= []).push(user);
  return result;
}, {});
```

```js
  { id: 1, name: "A" },
```

Result:

# 73. What is `flat()`?

`flat()` creates a new array with nested arrays flattened to a specified depth.

Result:

# 74. What is `flatMap()`?

`flatMap()` effectively performs a map followed by a one-level flatten.

Result:

# 75. How do you remove duplicates from an array?

The simplest approach for primitive values:

```js
const numbers = [1, 2, 2, 3, 3, 4];

const unique = [...new Set(numbers)];

console.log(unique);
// [1, 2, 3, 4]
```

For objects, `Set` doesn't deduplicate objects based on identical contents because objects are compared by identity.

Example:

```js
const users = [
  { id: 1, name: "A" },
  { id: 1, name: "A" }

```

You need key-based logic, for example:

```js
const uniqueUsers = [
  ...new Map(users.map(user => [user.id, user])).values()
];
```

# 6. Asynchronous JavaScript — Questions 76–90

## 76. What is synchronous programming?

Synchronous code executes sequentially.

```js
console.log("A");
console.log("B");
console.log("C");
```

Output:

```text
A
B
C
```

Each operation generally completes before the next statement executes.

---

# 77. What is asynchronous programming?

Asynchronous programming allows operations such as timers, network requests, or I/O to complete later without blocking the current JavaScript execution flow.

Example:

```js
console.log("A");

setTimeout(() => {
  console.log("B");
}, 1000);

console.log("C");
```

Output:

```text
A
C
B
```

---

# 78. What is the Event Loop?

The Event Loop coordinates JavaScript execution with asynchronous work.

Simplified browser model:

```text
        JavaScript
           │
      Call Stack
           │
           ↓
   Web/Platform APIs
           │
           ↓
     Task Queues
           │
           ↓
       Event Loop
           │
           └──→ Call Stack
```

The exact architecture differs between browsers and Node.js, but the fundamental idea is that JavaScript execution is coordinated with queued asynchronous callbacks.

### Critical Interview Point

Promise reactions use the **microtask queue**, while timers and many event callbacks use task queues.

Microtasks are processed at defined checkpoints before the event loop proceeds to another task.

---

# 79. What is the Call Stack?

The Call Stack tracks currently executing function calls.

```js
function a() {
  b();
}

function b() {
  console.log("Hello");
}

a();
```

Conceptually:

```text
a()
 ↓
b()
 ↓
console.log()
```

Functions are pushed onto the stack and removed when they return.

---

# 80. What is the Callback Queue?

The term "callback queue" is often used broadly for queues holding callbacks that are ready to run.

In browser terminology, it's more accurate to distinguish **tasks** and **microtasks**.

Examples of task sources include:

```text
setTimeout callbacks
DOM events
some I/O-related callbacks
```

Promise reactions go into the **microtask queue**.

### Important Interview Trap

Don't say:

> "All asynchronous callbacks go into one callback queue."

That's an oversimplification.

# 81. What are Promises?

A Promise represents the eventual result of an asynchronous operation.

```js
const promise = fetch("/api/users");
```

A Promise can eventually:

```text
Fulfill
or
Reject
```

Example:

```js
const promise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Success");
  } else {
    reject(new Error("Failed"));
  }
});
```

---

# 82. What are the states of a Promise?

A Promise has three states:

```text
Pending
   ↓
Fulfilled

or

Pending
   ↓
Rejected
```

Once fulfilled or rejected, it is **settled**.

A settled Promise cannot transition to another state.

---

# 83. What is Promise chaining?

Promise chaining means connecting asynchronous operations using `.then()`.

```js
fetchUser()
  .then(user => getOrders(user.id))
  .then(orders => processOrders(orders))
  .catch(error => {
    console.error(error);
  });
```

Each `.then()` returns a new Promise.

This enables sequential asynchronous workflows.

---

# 84. What is `Promise.all()`?

`Promise.all()` runs/awaits multiple promises and fulfills when **all** fulfill.

```js
const result = await Promise.all([
  fetchUsers(),
  fetchProducts(),
  fetchOrders()
]);
```

If any Promise rejects:

```text
Promise.all()
      ↓
Rejected
```

It is useful when all operations are required.

### Example

```js
const [users, products] = await Promise.all([
  getUsers(),
  getProducts()
]);
```

This allows independent operations to proceed concurrently rather than waiting for one before starting the next.

---

# 85. What is `Promise.race()`?

`Promise.race()` settles when the **first input Promise settles**.

That means the first result can be either:

```text
fulfillment
or
rejection
```

Example:

```js
const result = await Promise.race([
  request1(),
  request2()
]);
```

---

# 86. What is `Promise.allSettled()`?

`Promise.allSettled()` waits for **all promises to settle**, regardless of whether they fulfill or reject.

```js
const results = await Promise.allSettled([
  task1(),
  task2(),
  task3()
]);
```

Results look conceptually like:

```js
[
  { status: "fulfilled", value: ... },
  { status: "rejected", reason: ... },
  { status: "fulfilled", value: ... }
]
```

Useful when every operation's outcome matters.

---

# 87. What is `Promise.any()`?

`Promise.any()` fulfills as soon as **one input Promise fulfills**.

```js
const result = await Promise.any([
  server1(),
  server2(),
  server3()
]);
```

If all inputs reject, it rejects with an `AggregateError`.

### Compare

```text
all()
→ all must fulfill

race()
→ first to settle

allSettled()
→ wait for all

any()
→ first to fulfill
```

---

# 88. What are `async` and `await`?

`async` makes a function return a Promise.

```js
async function getUser() {
  return { name: "Ashok" };
}
```

`await` pauses execution within the async function until the Promise settles.

```js
async function load() {
  const user = await getUser();

  console.log(user);
}
```

### Important

`await` does **not block the entire JavaScript runtime**. It suspends the current async function's continuation while other work can proceed.

---

# 89. How does error handling work with async/await?

Use `try/catch`.

```js
async function loadData() {
  try {
    const response = await fetch("/api/data");

    if (!response.ok) {
      throw new Error("Request failed");
    }

    return await response.json();
  } catch (error) {
    console.error(error);
  }
}
```

### Important `fetch()` interview point

`fetch()` normally rejects for **network-level failures**, but an HTTP `404` or `500` does not by itself cause the Promise to reject.

You commonly need:

```js
if (!response.ok) {
  throw new Error("HTTP error");
}
```

# 90. Common pitfalls of asynchronous JavaScript

### 1. Accidental sequential execution

Bad when operations are independent:

```js
const a = await getA();
const b = await getB();
```

Potentially better:

```js
const [a, b] = await Promise.all([
  getA(),
  getB()
]);
```

### 2. Forgetting to await

```js
const data = getData();

console.log(data);
```

`data` is a Promise, not the resolved value.

### 3. Unhandled Promise rejection

```js
doSomethingAsync();
```

without appropriate error handling can cause problems.

### 4. Mixing callback and Promise styles unnecessarily

### 5. Blocking the event loop

CPU-heavy synchronous work can prevent other callbacks from executing.

### 6. Incorrect loop handling

A common mistake:

```js
items.forEach(async item => {
  await process(item);
});
```

`forEach()` doesn't await the returned Promises.

For sequential processing:

```js
for (const item of items) {
  await process(item);
}
```

For concurrent processing:

```js
await Promise.all(
  items.map(item => process(item))
);
```

### 7. Race conditions

Multiple asynchronous operations may update shared state in an unexpected order.

# 91. What is the DOM?

DOM = **Document Object Model**.

The browser represents an HTML document as a tree-like object structure.

Example:

```html

  <h1>Hello</h1>
</div>
```

Conceptually:

```text
Document
   ↓
 div
   ↓
 h1
   ↓
 "Hello"
```

JavaScript can interact with it:

```js
const title = document.querySelector("h1");

title.textContent = "Welcome";
```

### Interview Answer

> The DOM is the browser's object representation of an HTML document, allowing JavaScript and other APIs to inspect and modify document structure, content, and state.

# 92. What is event delegation?

Event delegation means attaching one event handler to a parent rather than individual child elements.

```html
<ul id="users">
  <li>User 1</li>
  <li>User 2</li>
  <li>User 3</li>
</ul>
```

```js
document
  .querySelector("#users")
  .addEventListener("click", event => {
    const item = event.target.closest("li");

    if (item) {
      console.log(item.textContent);
    }
  });
```

### Advantages

- Fewer event handlers
    
- Works well with dynamically added children
    
- Centralized event handling
    

---

# 93. What is event bubbling?

During bubbling, an event propagates from the target toward its ancestors.

```text
Target
  ↑
Parent
  ↑
Grandparent
  ↑
Document
```

Example:

```js
parent.addEventListener("click", () => {
  console.log("Parent");
});

child.addEventListener("click", () => {
  console.log("Child");
});
```

Clicking the child normally produces:

```text
Child
Parent
```

You can stop propagation:

```js
event.stopPropagation();
```

Use this carefully; indiscriminate use can make event behavior harder to reason about.

---

# 94. What is event capturing?

Capturing is the earlier propagation phase where the event travels from ancestors toward the target.

```text
Document
   ↓
Parent
   ↓
Child
```

You can register a capturing listener:

```js
parent.addEventListener(
  "click",
  handler,
  { capture: true }
);
```

### Event flow

The simplified event lifecycle is:

```text
Capturing
    ↓
Target
    ↓
Bubbling
```

Not every event behaves identically, but this is the standard propagation model.

# 95. What is debouncing?

Debouncing waits until activity stops for a specified period before executing a function.

Example use cases:

- Search box
    
- Auto-save
    
- Window resize handling
    

Conceptually:

```text
User types:
A → B → C → D

Timer resets after every input

       pause
        ↓
     Execute
```

Example implementation:

```js
function debounce(fn, delay) {
  let timer;

  return (...args) => {
    clearTimeout(timer);

    timer = setTimeout(() => {
      fn(...args);
    }, delay);
  };
}
```

# 97. What is memoization?

Memoization caches the result of an expensive function based on its inputs.

```js
function memoize(fn) {
  const cache = new Map();

  return function (value) {
    if (cache.has(value)) {
      return cache.get(value);
    }

    const result = fn(value);

    cache.set(value, result);

    return result;
  };
}
```

Example:

```js
const square = memoize(x => x * x);

square(10); // calculates
square(10); // cached
```

### Important

Memoization consumes memory, so it should be used when the computation is expensive enough and the cache strategy is appropriate.

# 98. What causes memory leaks in JavaScript applications?

A memory leak occurs when objects that are no longer logically needed remain reachable and therefore cannot be garbage-collected.

Common causes:

### 1. Forgotten event listeners

```js
element.addEventListener("click", handler);
```

If the listener and related references remain unnecessarily alive, memory can accumulate.

### 2. Timers

```js
setInterval(() => {
  // ...
}, 1000);
```

If no longer needed, clear it:

```js
clearInterval(id);
```

### 3. Large global objects

```js
window.largeCache = hugeObject;
```

### 4. Growing caches

```js
const cache = new Map();
```

If entries are never removed, memory can grow indefinitely.

### 5. Detached DOM nodes

JavaScript still holding references to removed DOM elements can keep associated objects alive.

### 6. Closures

Closures aren't leaks by themselves, but a long-lived closure can retain references to large objects longer than intended.

### Senior Interview Answer

> Memory leaks occur when objects remain reachable through references even though the application no longer needs them. I look for retained event listeners, timers, growing caches, detached DOM nodes, subscriptions, and long-lived closures.

## 1. Implement a Custom `map()`

### Concept

`map()` transforms every element of an array and returns a **new array**.

### Implementation

```javascript
Array.prototype.myMap = function (callback) {
    const result = [];

    for (let i = 0; i < this.length; i++) {
        result.push(callback(this[i], i, this));
    }

    return result;
};

const numbers = [1, 2, 3, 4];

const result = numbers.myMap(x => x * 2);

console.log(result);
// [2, 4, 6, 8]
```

### Interview Answer

> "`map()` iterates over an array, applies a callback to each applicable element, and returns a new transformed array without modifying the original array."

**Senior point:** Be aware of sparse arrays and the native method's exact semantics before claiming a custom implementation is fully equivalent.

# 3. Implement a Custom `reduce()`

This is one of the **most important JavaScript interview coding questions**.

```javascript
Array.prototype.myReduce = function (callback, initialValue) {
    let accumulator;
    let startIndex = 0;

    if (arguments.length >= 2) {
        accumulator = initialValue;
    } else {
        accumulator = this[0];
        startIndex = 1;
    }

    for (let i = startIndex; i < this.length; i++) {
        accumulator = callback(
            accumulator,
            this[i],
            i,
            this
        );
    }

    return accumulator;
};

);

// 10
```

# 4. Implement Debounce

### Concept

**Debounce** means:

> Execute the function only after the calls have stopped for a specified amount of time.

Common use cases:

- Search box
    
- Autosave
    
- Resize
    
- Form validation
    

### Implementation

```javascript
function debounce(fn, delay) {
    let timer;

    return function (...args) {
        clearTimeout(timer);

        timer = setTimeout(() => {
            fn.apply(this, args);
        }, delay);
    };
}
```

### Example

```javascript
const search = debounce((value) => {
    console.log("API call:", value);
}, 500);

search("j");
search("ja");
search("jav");
search("java");
```

Only the final call is executed after 500 ms of inactivity.

### Interview Answer

> "Debouncing delays execution until a period of inactivity has occurred. It is useful when we don't want to execute expensive operations for every user event."

# 5. Implement Throttle

### Concept

**Throttle** limits how frequently a function can execute.

```javascript
function throttle(fn, delay) {
    let lastExecution = 0;

    return function (...args) {
        const now = Date.now();

        if (now - lastExecution >= delay) {
            lastExecution = now;
            fn.apply(this, args);
        }
    };
}
```

### Example

```javascript
const handleScroll = throttle(() => {
    console.log("Scrolling...");
}, 200);

window.addEventListener("scroll", handleScroll);
```

### Debounce vs Throttle

|Debounce|Throttle|
|---|---|
|Waits for inactivity|Limits execution frequency|
|Executes after activity stops|Executes at controlled intervals|
|Search input|Scroll|
|Autosave|Mouse movement|
|Resize|Window events|

### Interview Answer

> "I use debounce when I care about the final event after activity stops, and throttle when I need controlled periodic execution during continuous activity."

# 6. Reverse a String Without Built-in Methods

### Basic approach

```javascript
function reverseString(str) {
    let result = "";

    for (let i = str.length - 1; i >= 0; i--) {
        result += str[i];
    }

    return result;
}

console.log(reverseString("JavaScript"));
// tpircSavaJ
```

### Interview Answer

> "I iterate from the last character to the first and construct a new string."

# 7. Find Duplicate Elements in an Array

### Using `Set`

```javascript
function findDuplicates(array) {
    const seen = new Set();
    const duplicates = new Set();

    for (const value of array) {
        if (seen.has(value)) {
            duplicates.add(value);
        } else {
            seen.add(value);
        }
    }

    return [...duplicates];
}

console.log(
    findDuplicates([1, 2, 3, 2, 4, 1, 5])
);

// [2, 1]
```

### Interview Answer

> "I use a Set to track values already encountered and another Set to store duplicates. This gives average O(n) time and O(n) additional space."

### Alternative with frequency counting

```javascript
function findDuplicates(array) {
    const count = new Map();

    for (const value of array) {
        count.set(value, (count.get(value) || 0) + 1);
    }

    return [...count.entries()]
        .filter(([_, frequency]) => frequency > 1)
        .map(([value]) => value);
}
```

# 8. Flatten a Nested Array

```javascript
function flatten(array) {
```

# 9. Implement a Promise From Scratch

This is a **senior-level interview question**.

A production-quality Promise implementation is complex because the real specification includes thenable assimilation, microtask scheduling, resolution procedures, multiple edge cases, and combinators.

For an interview, you can demonstrate the core state-machine concept:

```javascript
class MyPromise {
    constructor(executor) {
        this.state = "pending";
        this.value = undefined;

        this.onFulfilled = [];
        this.onRejected = [];

        const resolve = (value) => {
            if (this.state !== "pending") return;

            this.state = "fulfilled";
            this.value = value;

            this.onFulfilled.forEach(fn => fn(value));
        };

        const reject = (reason) => {
            if (this.state !== "pending") return;

            this.state = "rejected";
            this.value = reason;

            this.onRejected.forEach(fn => fn(reason));
        };

        try {
            executor(resolve, reject);
        } catch (error) {
            reject(error);
        }
    }

    then(onFulfilled, onRejected) {
        if (this.state === "fulfilled") {
            onFulfilled?.(this.value);
        }

        if (this.state === "rejected") {
            onRejected?.(this.value);
        }

        if (this.state === "pending") {
            if (onFulfilled) {
                this.onFulfilled.push(onFulfilled);
            }

            if (onRejected) {
                this.onRejected.push(onRejected);
            }
        }

        return this;
    }
}
```

### Example

```javascript
const promise = new MyPromise((resolve) => {
    setTimeout(() => {
        resolve("Success");
    }, 1000);
});

promise.then(value => {
    console.log(value);
});
```

### Interview Answer

> "A Promise is essentially a state machine that starts in pending state and transitions only once to fulfilled or rejected. A real implementation also needs proper thenable resolution, asynchronous handler execution, chaining, error propagation, and other specification details."

**Important:** Don't claim the simple implementation above is a spec-compliant replacement for native `Promise`.

# 10. Closure-Based Output Questions

This is extremely common in senior JavaScript interviews.

## Example 1

```javascript
function outer() {
    let count = 0;

    return function () {
        count++;
        console.log(count);
    };
}

const fn = outer();

fn();
fn();
fn();
```

### Output

```text
1
2
3
```

### Why?

The inner function forms a **closure** over `count`.

Even though `outer()` has finished executing, the returned function still has access to its lexical environment.

### Interview Answer

> "A closure occurs when a function retains access to variables from its lexical environment even after the outer function has finished execution."

---

# Example 2 — Independent Closures

```javascript
function counter() {
    let count = 0;

    return () => ++count;
}

const counter1 = counter();
const counter2 = counter();

console.log(counter1());
console.log(counter1());
console.log(counter2());
console.log(counter2());
```

### Output

```text
1
2
1
2
```

Why?

Each call to `counter()` creates a **separate lexical environment**.

```text
counter1 → count = 2

counter2 → count = 2
```

They don't share the same `count`.

# Example 3 — `var` Closure Trap

```javascript
for (var i = 0; i < 3; i++) {
    setTimeout(() => {
        console.log(i);
    }, 100);
```

### Output

```text
3
3
3
```

Why?

`var` is function-scoped, so all callbacks refer to the same `i`.

```javascript
for (let i = 0; i < 3; i++) {
```

```text
0
1
2
```

`let` creates a per-iteration binding in this `for` loop.
