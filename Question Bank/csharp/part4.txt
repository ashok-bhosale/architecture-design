Architect Scenario Discussions
Multi-Tenant SaaS Scenario
	Your SaaS application has 5,000 customers. Some enterprise customers require strict data isolation, while smaller customers prioritize lower costs.
	• Would you choose database-per-tenant, shared database, or a hybrid model?
	• How would you handle onboarding new tenants?
	• How would you approach tenant-specific migrations?

Auditing Scenario
	A healthcare application must maintain a complete history of every data change for seven years.
	• Would you implement auditing in EF Core, SQL Server, or both?
	• How would you ensure audit records cannot be tampered with?
	• What performance considerations would you evaluate?

Scaling Scenario
	An application receives 50,000 read requests per minute and 2,000 write requests per minute.
	• Would you introduce caching?
	• Would you use read replicas?
	• Would CQRS improve scalability?
	• How would you monitor database health?

Key Architect Principles for Part 2
Repository Usage
	• Avoid unnecessary abstraction.
	• Introduce repositories only when they provide clear business value.
	• Keep data access concerns separate from domain logic.
Multi-Tenancy
	• Design tenant isolation intentionally.
	• Align tenancy strategy with business requirements.
	• Consider operational complexity, cost, and compliance.
Auditing
	• Define auditing requirements early.
	• Ensure consistency across services.
	• Balance traceability with performance.
Scalability
	• Optimize reads separately from writes.
	• Use caching thoughtfully.
	• Plan for growth before performance becomes a crisis.

Architect Decision Frameworks
Performance
	• Prefer projections for APIs.
	• Use AsNoTracking() for read-heavy workloads.
	• Avoid N+1 queries.
	• Review execution plans regularly.
	• Benchmark before optimizing.
Reliability
	• Design for transient failures.
	• Apply retries thoughtfully.
	• Ensure idempotency where retries occur.
	• Monitor connection pool usage.
Security
	• Store secrets outside source control.
	• Limit data exposure through DTOs.
	• Apply least-privilege principles.
	• Review raw SQL carefully.
Governance
	• Establish migration review processes.
	• Standardize entity configurations.
	• Define conventions for auditing and soft deletes.
	• Perform periodic architecture assessments.
Distributed Systems
	• Avoid shared databases between independent services.
	• Favor eventual consistency over distributed transactions.
	• Use Outbox/Saga patterns where appropriate.
	• Recognize that scalability often requires accepting operational complexity.
